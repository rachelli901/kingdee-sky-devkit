1 手册说明与部署总览

1.1 适用范围

本手册面向将 KingdeeSky.DevKit 二开示例工程部署到自行部署的经典金蝶云·星空 V9.1（.NET Framework 4.8 + IIS）服务器环境，覆盖服务端插件与 WebAPI 客户端两类组件的部署、验证与回滚。

适用于企业版/标准版私有部署环境。公有云租户可参照第 5 章部署 WebAPI 客户端；插件侧须以服务商提供的部署通道为准。

版本锁定：本工程锁定星空 V9.1。插件与星空版本强绑定，请使用与目标环境补丁版本一致的 BOS 程序集；升级环境补丁后必须重新拷贝 DLL、重新编译，禁止混用其它版本程序集。

1.2 两类组件，两套部署动作

组件 交付形态 部署位置 是否依赖金蝶 DLL
KingdeeSky.Plugins 服务端插件类库 星空站点 WebSite\bin + BOS 设计器注册 编译期需要（不外发）
KingdeeSky.WebApiClient 控制台绿色程序 任意可访问星空站点的目录（建议独立目录或任务机） 完全不需要

1.3 部署总流程

  1. 部署前准备：核对环境与软件要求，准备账号权限，备份账套库与管理库。
  2. 构建产出交付包：运行一键构建，得到版本化 ZIP 包。
  3. 创建审计表：在账套库执行审计表脚本。
  4. 部署插件 DLL：拷贝 KingdeeSky.Plugins.dll 到站点 bin，回收 IIS 应用程序池。
  5. 注册插件：在 BOS 设计器中以“扩展”方式注册 8 个插件类。
  6. 部署 WebAPI 客户端：放到目标目录，修改非敏感配置，注入密钥。
  7. 自检与冒烟验证：运行 --selfcheck，再跑通业务全流程。
  8. 记录基线：登记本次版本与上一版本包，作为回滚基线。

2 部署前准备

2.1 环境与软件要求

项 要求
星空环境 已授权的经典星空 V9.1（私有部署、本机演示或单租户环境）
目标框架 .NET Framework 4.8（与星空 V9.1 对应）
Web 服务器 IIS（星空站点默认虚拟目录 /K3Cloud/）
数据库 SQL Server（审计表脚本为 SQL Server 语法）
构建机 可运行 csc.exe（.NET Framework 4.8）与 MSBuild（编译插件时）

2.2 账号与权限准备

  • 星空账号：具备 BOS 设计器（动态建模平台）访问权限，用于注册插件。
  • WebAPI 账号：具备采购订单等业务对象权限，并被授予 WebAPI 调用权限（第 5 章使用）。
  • 数据库权限：对目标账套库有建表权限。
  • 服务器权限：可写入站点 bin 目录，可回收 IIS 应用程序池（管理员命令行可执行 iisreset）。

2.3 备份与实施窗口

  1. 部署前对账套库与管理中心库做完整备份。
  2. 选择业务低峰期实施，通知相关用户。
  3. 先在相同补丁版本的测试/演示环境完整演练一遍，确认无误后再上生产；生产与测试的补丁版本应保持一致。

3 构建与打包

3.1 一键构建

在仓库根目录执行：

build.bat

等价于 powershell -NoProfile -ExecutionPolicy Bypass -File eng\build.ps1。脚本依次执行：

  1. 用 csc 编译 WebApiClient（Release，零金蝶 DLL 依赖）；
  2. 运行测试门禁（37 个用例：鉴权 / 密钥来源 / 配置分层 / 客户端调用链），任一失败立即中断并返回非 0；
  3. 若 lib\ 下已有所需 BOS DLL，则自动用 MSBuild 追加编译插件；
  4. 产出版本化 ZIP 到 artifacts\。

指定版本号：build.bat 1.1.0（不传则取 eng\version.txt）。

产物命名规则：

artifacts\KingdeeSky.DevKit-{版本号}-{yyyymmdd-HHMMSS}.zip

3.2 获取金蝶 BOS DLL 并编译插件

插件工程必须引用金蝶 BOS 程序集才能编译，这些 DLL 受金蝶许可协议保护，不能随示例代码分发，需从你拥有合法授权的星空应用服务器上拷贝：

  1. 在星空应用服务器上定位站点 bin 目录，常见位置为 C:\Program Files (x86)\Kingdee\K3Cloud\WebSite\bin\，或在 IIS 管理器查看 K3Cloud 站点物理路径下的 bin。
  2. 双击仓库 lib\copy-kingdee-dlls.bat，按提示粘贴该路径，脚本会校验并复制 4 个 DLL：Kingdee.BOS.dll、Kingdee.BOS.Core.dll、Kingdee.BOS.App.dll、Kingdee.BOS.Orm.dll。
  3. 再次运行 build.bat，脚本检测到 DLL 后会自动编译 KingdeeSky.Plugins 并把 KingdeeSky.Plugins.dll 打入交付包。

工程引用通过 $(KingdeeBinsDir) 属性指向 BOS 程序集目录（默认取 lib\）。需要从其它位置引用时用 msbuild KingdeeSky.Plugins.csproj /p:KingdeeBinsDir="D:\K3Cloud\WebSite\bin" 覆盖，无需改动工程文件。

3.3 交付包内容说明

交付包（ZIP）内主要成员如下：

路径 说明
WebApiClient\KingdeeSky.WebApiClient.exe(.config) WebAPI 客户端程序与其配置
WebApiClient\App.config.example / secrets.env.example 配置与密钥模板
Plugins\ 已编译的插件 DLL 与 PDB（lib\ 有 DLL 时才生成）
deploy\ 部署与调试指南、自定义单据指南、转换与反写指南、回滚预案、审计表 SQL
lib\ BOS DLL 清单说明与拷贝脚本
README.md / VERSION.txt 说明与本次版本号

4 服务端插件部署

4.1 创建审计表

在 SQL Server Management Studio 中选择目标账套数据库（不是管理中心库），执行 deploy\Scripts\T_SKY_AUDITLOG.sql。验证：

SELECT TOP 20 * FROM dbo.T_SKY_AUDITLOG ORDER BY FId DESC;

若不需要审计示例，可跳过本步，并在 BOS 中不注册对应的审核操作插件，其余插件不受影响。

4.2 拷贝插件 DLL 到站点 bin

  1. 取交付包 Plugins\KingdeeSky.Plugins.dll（调试期连同 .pdb 一起）。
  2. 拷贝到星空站点的 WebSite\bin 目录（与第 3.2 步取 DLL 的同一目录）。
  3. 只拷贝 KingdeeSky.Plugins.dll/.pdb，不要把 Kingdee.BOS.*.dll 拷进站点 bin（工程引用已设置 Private=False，编译输出中本就不含它们）。

多应用服务器（集群）：每一台 APP 服务器的站点 bin 都要拷贝，缺一台就可能间歇性报“找不到插件类”。

4.3 让新 DLL 生效

  • 热更新（替换已有 DLL 时）：示例类已标记 [HotUpdate]。需先在站点 WebSite\App_Data\Common.config 确认 IsEnablePlugInHotUpdate=true（部分补丁版本默认关闭）；开启后，对约 1 小时内替换的 DLL 直接生效，无需重启。
  • 首次部署（bin 中原本没有该 DLL）：必须回收程序池/重启 IIS，热更新只对“替换已有 DLL”有效。
  • 回收方式：IIS 管理器 → 应用程序池 → 回收 K3Cloud 对应程序池；或管理员命令行执行 iisreset。

4.4 在 BOS 设计器中注册插件

  1. 登录星空客户端或 HTML5 端，主控台搜索并打开 BOS 设计器（动态建模平台）。
  2. 标准单据（采购订单）：在业务领域展开 采购管理 → 找到 采购订单（FormId：PUR_PurchaseOrder）→ 右键 → 扩展（不要直接改标准单据，扩展元数据在升级补丁时不被覆盖）。
  3. 在扩展表单上按类型注册插件：表单插件在 编辑 → 表单插件；保存校验器在 编辑 → 操作列表 → 保存（Save）→ 校验器/操作校验；审核操作插件在 编辑 → 操作列表 → 审核（Audit）→ 服务插件。
  4. 注册框内填写“类全名, 程序集名”，可注册字符串见第 9 章速查表；自定义单据与转换/反写插件的注册入口不同（见 deploy\ 下对应指南）。
  5. 保存扩展元数据，列表中出现扩展与插件注册项即成功。

注册时下拉列表为空或找不到类：多为 DLL 未放到站点 bin，或类不是 public、缺少无参构造函数，或 DLL 编译框架版本高于目标环境。

5 WebAPI 客户端部署

5.1 部署位置与文件

WebApiClient 是绿色控制台程序，不在服务器写任何数据。将交付包 WebApiClient\ 下的 KingdeeSky.WebApiClient.exe、KingdeeSky.WebApiClient.exe.config 复制到目标目录（例如任务机 D:\apps\kingdee-webapi-client\）。

5.2 修改非敏感配置

编辑 KingdeeSky.WebApiClient.exe.config，只改站点与业务参数，不要写入任何密码：

键 说明
ServerUrl 站点根地址，私有部署填 http://{服务器IP}/K3Cloud/，公有云填租户站点地址（形如 https://{站点名}.kdcloud.com/）
AcctId 数据中心（账套）ID
UserName 调用账号（需有业务权限与 WebAPI 授权）
Lcid 2052 简体中文 / 1028 繁体 / 1033 英文
AuthMode password（默认）/ oauth2 / appsec
SecretStore env（默认）/ file / dpapi / kms
OrgNumber 等 仅建单场景需要，填账套内真实组织/供应商/物料/单据类型编号

账套 ID（AcctId）怎么查：私有部署在管理中心库执行 SELECT FDATACENTERID, FNAME FROM dbo.T_BAS_DATACENTER;；公有云在登录页选择数据中心后从页面或 URL 获取；不确定时先用主控台【公共设置 → 动态服务定义 → WebAPI】的在线测试页试登录，能登录的参数照搬即可。

5.3 注入密钥

密钥值只经密钥源注入，配置文件中只保留键名（默认 KINGDEE_PASSWORD 等）。按 SecretStore 选择一种方式：

密钥源 适用场景 注入方式
env 开发机 / CI 设置环境变量 KINGDEE_PASSWORD（Windows：set；Linux：export）
file 仅开发 在仓库之外维护明文密钥文件，按 secrets.env.example 格式，SecretsFile 指向它
dpapi 本地部署生产（推荐） 用 Windows DPAPI 加密后的密钥文件，DpapiFile 指向它，DpapiScope 选 CurrentUser 或 LocalMachine
kms 有 KMS/Vault 的环境 KmsBaseUrl 指向密钥服务，访问令牌存于 KmsTokenKey 指定的环境变量

生产环境推荐 dpapi（本地部署）或 kms（有统一密钥服务）；env/file 仅用于开发，不要在生产长期使用。

5.4 运行与菜单验证

运行 KingdeeSky.WebApiClient.exe。启动即登录，页头显示本次鉴权方式与密钥来源，随后进入交互菜单：

  1. 查询最近 10 张采购订单（只依赖登录成功，建议先跑通此项验证连通性）；
  2. 新建采购订单（保存为草稿，依赖组织/供应商/物料/单据类型编号）；
  3. 对指定内码单据执行提交 + 审核；
  4. 一键全流程：查询 → 建单 → 提交 → 审核 → 查看完整数据包。

6 部署后验证

6.1 运行自检

在部署目录执行：

KingdeeSky.WebApiClient.exe --selfcheck

自检以结构化 key=value 输出四类检查（版本 / 配置 / 密钥源 / 鉴权组件 / 传输层），不发起网络请求、不输出密钥值：返回码 0 表示全部就绪，1 表示存在未就绪项（逐项给出原因）。建议把该命令接入 CI 或部署脚本作为预检门禁。

6.2 冒烟测试

  1. --selfcheck 返回 0；
  2. 运行客户端，菜单 1 查询成功；
  3. 菜单 4 一键全流程跑通（建单 → 提交 → 审核 → 查看），状态流转正确；
  4. 插件侧按第 4.5 节清单逐项验证。

6.3 日志与观测

  • 程序日志经 SafeLogger 自动对已登记密钥脱敏，控制台与可选日志文件中的密钥均显示为掩码，确认日志中无明文密钥。
  • 插件侧审计写入可在 T_SKY_AUDITLOG 表中核对。
  • 记录本次部署的版本号与交付包文件名，作为下一次回滚的基线。

7 回滚与卸载

7.1 回滚触发条件

满足任意一条即启动回滚（先恢复服务，再离线排查）：--selfcheck FAIL 且 10 分钟内无法修复；登录成功率显著下降或不可用；关键业务（保存/提交/审核/下推）大面积报错且与本次发布相关；出现数据异常迹象（重复建单、反写错乱、审计缺失）。

有完整回滚预案见交付包 deploy\回滚预案.md，本节为要点摘录。

7.2 插件回滚

  1. 备份当前 WebSite\bin\KingdeeSky.Plugins.dll（保留现场）；
  2. 用上一版本 DLL 覆盖；
  3. 回收 IIS 应用程序池/重启站点；
  4. 在 BOS 设计器核对插件注册；冒烟单据全流程。

7.3 WebAPI 客户端回滚

  1. 找到上一版本包 artifacts\KingdeeSky.DevKit-{上一版本}-*.zip（发布纪律要求至少保留最近 2 个版本包）；
  2. 停用调用方，备份当前版本；
  3. 用上一版本覆盖 exe 与 .exe.config；
  4. 运行 --selfcheck 确认返回 0，再启用调用方并冒烟。

7.4 数据库脚本回滚

审计表 T_SKY_AUDITLOG 仅新增、不回改业务表。确认无程序写入后执行：

DROP TABLE dbo.T_SKY_AUDITLOG;

涉及业务表结构的脚本必须成对提供正向与反向脚本，升级脚本应保持幂等。

7.5 卸载

  1. BOS 设计器扩展中移除插件注册，或停用/删除扩展，恢复标准单据行为；
  2. 从站点 bin 删除 KingdeeSky.Plugins.dll/.pdb，回收应用程序池；
  3. 审计表可保留或删除；
  4. WebAPI 客户端为绿色程序，直接删除目录即可。

8 常见问题（FAQ）

Q1：构建时报“未能找到类型或命名空间名 Kingdee”？ A：lib\ 目录还没有金蝶 BOS DLL。运行 lib\copy-kingdee-dlls.bat，确认 4 个 DLL 与清单一致后重新构建。仅部署 WebApiClient 时可忽略并入包。

Q2：BOS 注册插件时列表里看不到我的类？ A：依次排查：DLL 未放到站点 bin；类不是 public；缺少无参构造函数；DLL 编译框架版本高于环境（如用 4.8 编译却部署到只装了 4.5 的环境）。

Q3：改了插件代码重新部署没反应？ A：先确认 DLL 文件时间已更新；回收 K3Cloud 应用程序池或执行 iisreset；集群环境逐台核对。

Q4：登录返回 LoginResultType 不是 1？ A：依次排查账套 ID、账号密码、Lcid、该用户是否有 WebAPI 权限、站点地址是否带正确虚拟目录（默认 /K3Cloud/）、HTTPS 证书是否被拦截；程序已打印失败响应原文，按 Message 定位。

Q5：Save 返回“字段不存在/基础资料不存在”？ A：多为基础资料编号（FNumber）或字段 Key 与账套不符。先用 WebAPI 在线测试页 View 一张已存在采购订单的真实数据包，对照修正配置。

Q6：可以在服务器上装 .NET Core / .NET 5+ 吗？ A：经典星空不需要 .NET Core，误装可能导致 IIS 程序池异常；二开工程坚持 .NET Framework（随星空版本，本工程为 4.8）。

Q7：生产部署有哪些硬性注意事项？ A：先在同补丁版本的测试环境回归；备份账套库与管理库；二开元数据走部署包、DLL 逐台 APP 拷贝并记录版本；标准补丁升级后回归全部插件；自定义表使用独立前缀（示例 T_SKY_），不要在金蝶标准表上加减列。

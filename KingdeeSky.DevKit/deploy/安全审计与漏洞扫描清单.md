# 安全审计与漏洞扫描清单

> 适用范围：`KingdeeSky.DevKit` 生产化过程中的安全与合规动作。
> 本文档区分两类：**已落地的自动化门禁**（本机即可验证）与**待接真实环境的审计项**（需授权星空环境/专业工具）。

---

## 1. 已落地的安全门禁（自动）

| # | 门禁 | 位置 | 触发时机 | 失败行为 |
|---|---|---|---|---|
| 1 | 明文密钥静态扫描 | `eng\scan-secrets.ps1`（入口 `scan-secrets.bat`） | `build.bat` 步骤 0 / CI “Secret scan” 步骤 / 手动执行 | `exit 1`，构建中断 |
| 2 | 传输安全策略（默认强制 HTTPS） | `TransportSecurityPolicy` | 客户端构造 + 每个请求前 | 未放行的 http 直接抛异常 |
| 3 | 弱协议移除（仅 TLS 1.2） | `Program.cs` 启动 | 进程启动 | — |
| 4 | 日志脱敏 | `SafeLogger` + `SecretRedactor` | 所有日志输出 | 密钥不出现在日志/响应 |
| 5 | 测试门禁 | `tests\run-tests.ps1` | `build.bat` 步骤 2 / CI | `exit 1`，构建中断 |
| 6 | `--selfcheck` 部署前预检 | `HealthCheck.cs` | 部署/CI 前手动或脚本触发 | `exit 1` |

### 1.1 静态扫描规则（`scan-secrets.ps1`）

- **高信号模式**：`-----BEGIN ... PRIVATE KEY-----` 私钥块、`AKIA[0-9A-Z]{16}`（AWS Access Key）、
  `gh[pousr]_...`（GitHub Token）、`sk-...`（OpenAI 风格密钥）。
- **键值模式**：敏感键名（password/secret/token/apikey/access_key/client_id/client_secret 等）后跟 `=`/`:` 的赋值；
  `.cs` 源码仅匹配**引号内字符串字面量**，避免赋值为从密钥源读取的方法调用/表达式时的误报。
- **过滤规则**：全大写 SNAKE（配置键名）、`{占位符}`、`CHANGE_ME`/`PLACEHOLDER`/`YOUR_`/`example`/`test`/`demo123` 均视为非真实密钥。
- **扫描范围**：默认排除 `.git/bin/obj/artifacts/packages/.vs/.idea/node_modules`、二进制/日志/示例扩展名；
  **默认不扫 `tests/`**（测试夹具值非生产密钥），加 `-IncludeTests` 可显式扫。

> 命令：`scan-secrets.bat`（或 `powershell -NoProfile -ExecutionPolicy Bypass -File eng\scan-secrets.ps1`）
> 干净输出：`Secret scan OK: scanned N files, no plaintext secrets found.`（exit 0）。

## 2. 待接真实环境的审计与漏洞扫描项（需要授权环境）

以下项**无法只用本机手段完成**，需在真实星空（V9.1 + 匹配补丁）环境或专业工具支持下执行：

| # | 审计/扫描项 | 方法/工具 | 输出 | 周期 |
|---|---|---|---|---|
| 1 | 服务端插件代码审计 | 人工 Code Review + 静态分析（如 VS Analyzer / ReSharper） | 问题清单与修复单 | 每次发布前 |
| 2 | WebAPI 端点漏洞扫描 | 授权范围内的动态扫描（OWASP ZAP / Burp Suite） | 扫描报告与误报剔除 | 发布前 + 季度 |
| 3 | 依赖/供应链核验 | `lib/` 中 4 个金蝶 DLL 的版本与哈希核对（与目标补丁包一致） | DLL 基线清单 | 每次补丁升级 |
| 4 | 密钥轮换演练 | DPAPI/KMS 换钥 + 客户端重连验证 | 轮换操作手册留痕 | 半年一次 |
| 5 | 权限最小化审计 | 服务账号/数据库账号/WebAPI 用户权限复核 | 权限矩阵 | 半年一次 |
| 6 | 审计日志核验 | `T_SKY_AUDITLOG` 落库完整性 + 留存策略 | 日志抽样报告 | 季度 |
| 7 | 传输层复核 | 确认生产站点仅开放 HTTPS、证书有效、`AllowInsecureHttp=false` | 部署清单勾选 | 每次发布 |
| 8 | 备份与恢复演练 | 按《回滚预案.md》演练数据/程序集回滚 | 演练记录 | 半年一次 |

## 3. 本机可即时执行的复核命令

```bash
# 1) 明文密钥扫描（构建门禁同款）
scan-secrets.bat

# 2) 跑全部单元用例（含传输安全/AppSec 签名器用例）
tests\run-tests.bat

# 3) 部署前自检（无需连接星空；返回 0=就绪）
KingdeeSky.WebApiClient.exe --selfcheck

# 4) 确认仓库内无真实密钥被跟踪
git ls-files | grep -iE "(secret|password|\.env$)" 
```

## 4. CI 中的安全门禁

`.github/workflows/ci.yml` 流水线顺序：

1. `Secret scan`：显式跑 `eng/scan-secrets.ps1`（命中即失败）
2. `Build, test and package`：`eng/build.ps1 -SkipSecretScan`（编译 → 测试门禁 → 打包）
3. `Upload package`：上传 `artifacts/*.zip`

> 在 push / PR 上自动执行；任何一步失败即阻断合并，保证**入库即无明文密钥、无编译失败、无测试失败**。

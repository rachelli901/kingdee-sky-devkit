# 生产部署与回滚预案（KingdeeSky.DevKit）

> 适用范围：本仓库改造后的生产化工程（金蝶云·星空 V9.1，.NET Framework 4.8）。
> 目标：每一次发布可复现、可验证、可回滚；异常发生时能在最短时间内恢复服务。

## 1. 版本化产物约定

- 一键构建入口：仓库根目录 `build.bat`（或 CI 中 `powershell -File eng/build.ps1`）。
- 构建产物统一输出到 `artifacts/`，命名规则：

  ```
  KingdeeSky.DevKit-<版本号>-<yyyymmdd-HHMMSS>.zip
  例：KingdeeSky.DevKit-1.0.0-20261022-231202.zip
  ```

- 版本号来源：`eng/version.txt`（按语义化版本维护，发版时递增）。
- 发布纪律：
  - **至少保留最近 2 个版本包**，禁止覆盖旧包；回滚必须能拿到上一版本。
  - 包内 `VERSION.txt` 与 `README.md` 随包发布，记录该版本的构建时间与内容。

## 2. 部署前检查清单

每次发布前逐项确认（任一 FAIL 即中止发布）：

1. 测试门禁通过：`tests\run-tests.bat` 返回 0（62 用例全绿）。
2. 自检通过：对目标环境注入密钥后运行
   `KingdeeSky.WebApiClient.exe --selfcheck`，返回码 0、无 FAIL 项。
3. 配置核对：生产 `App.config` 与 `App.config.example` 的差异仅限允许项（ServerUrl / AcctId / UserName / 演示编号）。
4. 密钥核对：仓库内无明文密钥；密钥值只通过环境变量 / 本地密钥文件 / DPAPI / KMS 注入。
5. 版本核对：本次发布的目标版本与 `eng/version.txt` 一致；Plugins 与 WebApiClient 使用同一批次产物。

## 3. 正常发布步骤

### 3.1 WebApiClient 集成程序

1. 从 `artifacts/` 取得目标版本 zip，解压到发布目录（如 `D:\apps\kingdee-webapi-client\`）。
2. 停用调用方（任务计划 / 定时作业 / 对接服务），避免发布期间产生脏调用。
3. 备份当前 `KingdeeSky.WebApiClient.exe` 与 `.exe.config` 到 `backup\<日期>\`。
4. 覆盖 exe、exe.config；如密钥键名变化，同步注入新密钥；`appSettings` 非敏感项按环境修改。
5. 启动前运行 `--selfcheck`，确认返回 0。
6. 启用调用方，冒烟验证：登录 + 查询最近单据。

### 3.2 星空插件（KingdeeSky.Plugins）

1. 在同一批次产物中取 `Plugins/` 下程序集（本仓库交付包包含，正式分发包中 DLL 需在授权环境编译/拉取）。
2. 拷贝到星空站点 bin 目录（常见 `%星安装目录%\WebSite\bin`，以实施环境为准）。
3. 回收 IIS 应用池（或重启站点）使新程序集生效。
4. 在 BOS 设计器中核对插件类注册与版本，无缺类告警。
5. 冒烟：新建/提交/审核对应单据（采购订单、差旅费报销单、下推转换与反写）。

## 4. 回滚触发条件

满足任意一条即启动回滚流程（先恢复服务，再排查原因）：

- `--selfcheck` FAIL 且 10 分钟内无法定位修复。
- 登录成功率显著下降或完全不可用（对比发布前基线，如 < 90%）。
- 关键业务报错（保存 / 提交 / 审核 / 下推）大面积出现，且错误与本次发布相关。
- 数据异常迹象（重复建单、反写错乱、审计记录缺失）。

> 决策原则：**回滚优先于排查**。发布失败时先回滚到上一版本恢复服务，再离线分析问题，不要在生产上长时间修复。

## 5. 回滚步骤

### 5.1 WebApiClient 集成程序回滚

1. 确认上一版本包存在：`artifacts\KingdeeSky.DevKit-<上一版本>-*.zip`；无包时用 `backup\<日期>\` 备份。
2. 停用调用方。
3. 备份当前（异常）版本到 `backup\<回滚日期>\`，保留现场供分析。
4. 用上一版本覆盖 `KingdeeSky.WebApiClient.exe` 与 `.exe.config`。
5. 如密钥键名随版本变化，恢复对应键名（值不变则沿用当前注入）。
6. 运行 `--selfcheck` 确认返回 0。
7. 启用调用方，冒烟：登录 + 查询 + 一笔建单全流程。

### 5.2 星空插件回滚

1. 备份当前 `%星安装目录%\WebSite\bin\KingdeeSky.Plugins.dll`（保留现场）。
2. 用上一版本 DLL 覆盖。
3. 回收 IIS 应用池/重启站点。
4. BOS 平台核对插件注册；冒烟单据全流程（新建/提交/审核/反写）。

### 5.3 数据库脚本回滚

- 本工程附带脚本 `deploy/Scripts/T_SKY_AUDITLOG.sql` 仅新增审计表 `T_SKY_AUDITLOG`，不回改业务表。
- 回滚：确认无程序再写入后执行：

  ```sql
  DROP TABLE T_SKY_AUDITLOG;
  ```

- 升级脚本必须保持幂等（建表前判断对象是否存在），确保重复执行与回滚重放安全。
- 涉及业务表结构变更的脚本（未来演化）必须同时提供正向与反向脚本，并在发布包中成对登记。

## 6. 回滚后验证

- `--selfcheck` 返回 0，无 FAIL 项。
- 日志服务/控制台无异常堆积；脱敏日志中无密钥值泄露。
- 业务冒烟通过：登录、查询、建单、提交、审核。
- 数据核对：审计表计数正常、单据状态与发布前一致。
- 将本次事故登记到复盘清单（见下），并确认回滚后基线稳定运行 ≥ 1 小时再决定是否重新发布。

## 7. 事故复盘清单

1. 触发原因归类：配置 / 网络 / 版本 / 权限 / 数据 / 依赖。
2. 影响范围与时长（哪个服务、多少调用、多久）。
3. 回滚决策是否及时，预案哪些步骤需要优化。
4. 需要补充的回归用例或自检项（写入 `tests/` 或 `--selfcheck`）。
5. 更新《部署与调试指南》与本文档，形成闭环。

## 8. 版本与兼容性红线

- 本仓库锁定金蝶云·星空 **V9.1**（.NET Framework 4.8）：
  - 升级星空版本必须同步升级 Plugins 引用的 BOS DLL（通过
    `msbuild -p:KingdeeBinsDir=<目标版本bin>` 重新编译），并回归插件测试。
  - 禁止把不同星空版本的插件 DLL 混在同一站点部署。
- WebApiClient 零金蝶 DLL 依赖，仅依赖 .NET Framework 4.8 运行时；跨版本兼容性由接口契约保障，升级前仍须以真实环境冒烟为准。
- 密钥体系（环境变量 / file / DPAPI / KMS）与鉴权方式（password / oauth2 / appsec）切换属配置变更，按第 2 节清单验证后再发布。

# 金蝶云·星空二开示例 —— 部署与调试指南

> 适用：经典金蝶云·星空企业版/标准版（V7/V8/V9，.NET Framework + IIS）。
> 不同补丁版本的菜单措辞可能略有差异，操作逻辑一致。请在**测试/演示环境**先验证，再上生产。

---

# Part A　服务端插件（KingdeeSky.Plugins）

## A1. 获取并引用 Kingdee.BOS.* DLL

插件工程必须引用金蝶 BOS 程序集才能编译。这些 DLL 不分发，从你授权的应用服务器取：

1. 在星空应用服务器上找到站点 bin 目录，常见位置：
   - `C:\Program Files (x86)\Kingdee\K3Cloud\WebSite\bin\`
   - `C:\Program Files\Kingdee\K3Cloud\WebSite\bin\`
   - IIS 自定义部署：打开 IIS 管理器 → 站点 K3Cloud → 右键“管理网站→浏览”，其下的 `bin`
2. 双击本仓库 `lib/copy-kingdee-dlls.bat`，粘贴该路径，脚本会校验并复制：
   `Kingdee.BOS.dll`、`Kingdee.BOS.Core.dll`、`Kingdee.BOS.App.dll`、`Kingdee.BOS.Orm.dll`。
3. Visual Studio 中重新生成 `KingdeeSky.Plugins`。

> 多环境开发时，建议保留“每个补丁版本一个 lib 副本”，避免高版本 DLL 编译的插件部署到低版本环境。

## A2. 创建审计表（操作插件示例依赖）

在 SQL Server Management Studio 中**选择目标账套数据库（不是管理中心库）**，执行
`deploy/Scripts/T_SKY_AUDITLOG.sql`。验证：

```sql
SELECT TOP 20 * FROM dbo.T_SKY_AUDITLOG ORDER BY FId DESC;
```

若不需要审计示例，可跳过本步，并在 BOS 中不注册 `PurchaseOrderAuditOpPlugin`，其余两个插件不受影响。

## A3. 在 BOS 设计器中注册插件（推荐“扩展”方式）

1. 登录星空客户端或 HTML5 端，主控台搜索并打开 **BOS 设计器**（动态建模平台）。
2. 在左侧业务领域中展开 **采购管理**，找到 **采购订单**（FormId：`PUR_PurchaseOrder`），
   右键 → **扩展**（不要直接打开标准单据修改；扩展会生成你自己的扩展元数据，升级补丁不被覆盖）。
3. 在扩展表单上分别注册三类插件：

| 示例类 | 注册入口 |
|---|---|
| `PurchaseOrderFormPlugin`（表单插件） | 扩展表单窗口菜单 **编辑 → 表单插件**（或表单属性面板中的“表单插件”）→ **注册插件** → 粘贴类全名 → 确定 |
| `PurchaseOrderSaveValidator`（保存校验） | 菜单 **编辑 → 操作列表**（或表单上的“操作”节点）→ 选中 **保存（Save）** 操作 → 编辑 → **校验器/操作校验** 页签 → 新增 → 注册插件 |
| `PurchaseOrderAuditOpPlugin`（审核操作） | 同一“操作列表” → 选中 **审核（Audit）** 操作 → 编辑 → **服务插件** 页签 → 新增 → 注册插件 |

注册框中填写的“类全名, 程序集名”（可直接复制）：

```
KingdeeSky.Plugins.PurchaseOrder.PurchaseOrderFormPlugin, KingdeeSky.Plugins
KingdeeSky.Plugins.PurchaseOrder.PurchaseOrderSaveValidator, KingdeeSky.Plugins
KingdeeSky.Plugins.PurchaseOrder.PurchaseOrderAuditOpPlugin, KingdeeSky.Plugins
```

> 另外两类场景的注册入口不同，不要注册到标准单据扩展上：
> - 自定义单据（差旅费报销单）三个插件：见同目录《自定义单据开发指南.md》第 4 节
>   （表单插件、保存校验器、审核服务插件，注册在你新建的 SKY_ExpReimburse 上）；
> - 转换插件注册在**转换规则的插件策略**、反写插件注册在**下游单据的业务流程服务插件节点**：
>   见同目录《单据转换与反写插件指南.md》第 2、4 节。

4. 保存扩展元数据。BOS 设计器列表中能看到你的扩展与插件注册项即成功。
5. （可选，跨环境迁移）用 BOS 的 **解决方案 → 部署包管理** 把扩展打成二开部署包，
   在目标环境导入；插件 DLL 仍需按 A4 手工拷贝到各应用服务器。

> 注册时下拉列表为空/找不到类：99% 是 DLL 未放到站点 bin（见 A4），或类不是 `public`、
> 没有无参构造函数。本示例均已满足。

## A4. 部署插件 DLL

1. 编译输出：`src/KingdeeSky.Plugins/bin/Debug/KingdeeSky.Plugins.dll`
   （调试时连同 `KingdeeSky.Plugins.pdb` 一起，才能命中断点）。
2. 拷贝到星空站点的 `WebSite\bin`（即 A1 中取 DLL 的同一目录）。
3. 生效方式：
   - 示例类已标记 `[HotUpdate]`（`Kingdee.BOS.Util.HotUpdateAttribute`）。热更新需先在站点
     `WebSite\App_Data\Common.config` 中确认 `IsEnablePlugInHotUpdate=true`（部分补丁版本默认关闭）；
     开启后，对**约 1 小时内**替换的插件 DLL 直接生效，无需重启；
   - **首次部署**（bin 中原本没有该 DLL）仍需回收程序池/重启 IIS，热更新只对“替换已有 DLL”有效；
   - 若替换后未生效：IIS 管理器 → 应用程序池 → 回收 K3Cloud 对应程序池；
     或管理员命令行执行 `iisreset`；
   - **多应用服务器（集群）**：每一台 APP 的站点 bin 都要拷贝。
4. 只拷贝 `KingdeeSky.Plugins.dll/.pdb`。**不要**把 `Kingdee.BOS.*.dll` 拷进站点 bin
   （工程引用已设置 `Private=False`，编译输出里本来就不会有它们）。

## A5. 附加进程调试（类库不能 F5）

1. 浏览器打开一次星空站点并登录，触发 IIS 工作进程启动。
2. Visual Studio 以**管理员身份**运行 → 菜单 **调试 → 附加到进程**：
   - 勾选“显示所有用户的进程”；
   - 本地 IIS 部署：附加 **`w3wp.exe`**（多个 w3wp 时可全选，或用下面命令按应用程序池定位 PID）；
   - 协同开发云/IIS Express：附加 **`iisexpress.exe`**。
3. 在插件代码中打断点（如 `DataChanged`、`Validate`、`BeforeExecuteOperationTransaction`），
   在星空界面新增/保存/审核采购订单，断点命中即可调试。
4. 定位 w3wp 对应程序池（管理员命令行）：

```cmd
%windir%\System32\inetsrv\appcmd list wp
```

5. 修改代码后重新生成 → 重新拷贝 DLL（[HotUpdate] 在热更新开关开启且 1 小时窗口内免重启；
   断点不命中就回收程序池再附加；首次部署必须回收/重启一次）。

## A6. 验证清单

- [ ] 新建采购订单：表头备注出现“表单插件已加载”默认文字；
- [ ] 新增分录行：需求日期自动填为今天 +7 天；
- [ ] 修改数量或含税单价：价税合计自动重算；数量填负数会被纠正并提示；
- [ ] 保存时：数量为 0/为空、物料为空、需求日期早于今天，分别收到行级错误提示；
- [ ] 点审核：需求日期早于今天时，界面层先拦截；绕过界面（如用 WebAPI 建单后审核）时，
      操作插件在服务端再次拦截并返回 CancelMessage；
- [ ] 审核成功：`T_SKY_AUDITLOG` 表新增一条 Audit 记录，操作人/单据编号正确。

# Part B　WebAPI 客户端（KingdeeSky.WebApiClient）

## B1. 准备参数

编辑 `src/KingdeeSky.WebApiClient/App.config`：

| 键 | 说明 |
|---|---|
| `ServerUrl` | 站点根地址，私有部署如 `http://192.168.1.10/K3Cloud/`，公有云如 `https://xxx.kdcloud.com/` |
| `AcctId` | 数据中心（账套）ID，获取方式见 B2 |
| `UserName` / `Password` | 调用账号，需有采购订单权限与 WebAPI 授权 |
| `Lcid` | 2052 简体中文 / 1028 繁体 / 1033 英文 |
| `OrgNumber` 等 | 仅菜单 2/4 建单场景需要，填账套内真实编号 |

## B2. 账套 ID（AcctId）怎么查

- 私有部署：在管理中心数据库（默认库名类似 K3Cloud_Config / 管理库）执行
  `SELECT FDATACENTERID, FNAME FROM dbo.T_BAS_DATACENTER;`（字段随版本可能微调）；
- 公有云：登录页选择数据中心后，页面/URL 中可见数据中心标识，或向实施/服务商索取；
- 不确定时，先用主控台【公共设置 → 动态服务定义 → WebAPI】的**在线测试页**试登录，
  在线测试能登录的参数照搬到 App.config。

## B3. 运行

设 `KingdeeSky.WebApiClient` 为启动项目，F5；或命令行运行编译出的
`KingdeeSky.WebApiClient.exe`。启动即登录，成功后按菜单：

1. 查询最近 10 张采购订单（只依赖登录，**建议先跑通此项**）；
2. 新建采购订单（保存为草稿，依赖组织/供应商/物料/单据类型编号）；
3. 输入内码，提交并审核；
4. 一键全流程：查询 → 建单 → 提交 → 审核 → 查看完整数据包。

## B4. 常见基础资料 FormId（用于 ExecuteBillQuery 核对编号）

| 资料 | FormId | 常用字段 |
|---|---|---|
| 物料 | `BD_Material` | `FNumber, FName, FDocumentStatus` |
| 供应商 | `BD_Supplier` | `FNumber, FName, FDocumentStatus` |
| 组织 | `ORG_Organizations` | `FNumber, FName` |
| 采购订单 | `PUR_PurchaseOrder` | 见 Scenarios.cs |

单据类型编号（示例中的 `CGDD01_SYS`）各账套可能不同，可用
`ExecuteBillQuery("BD_BillType", "FNumber,FName", "FBillTypeID...")`
或直接在主控台“单据类型”基础资料中查看。

# Part C　常见问题 FAQ

**Q1：编译报“未能找到类型或命名空间名 Kingdee”？**
A：lib 目录还没有金蝶 DLL。运行 `copy-kingdee-dlls.bat`，确认 4 个 DLL 与 README 清单一致。

**Q2：BOS 注册插件时列表里看不到我的类？**
A：① DLL 没放到站点 bin；② 类不是 `public`；③ 没有无参构造函数；④ DLL 编译框架版本高于环境
（如用 4.8 编译却部署到只装了 4.5 的环境）。

**Q3：改了代码重新部署没反应？**
A：先确认 DLL 确实更新（看文件时间）；回收 K3Cloud 应用程序池或 `iisreset`；集群环境逐台检查。

**Q4：登录返回 LoginResultType 不是 1？**
A：依次排查：账套 ID 是否正确、账号密码、lcid、该用户是否有 WebAPI 权限、
站点地址是否带了正确的虚拟目录（默认 `/K3Cloud/`）、HTTPS 证书是否被拦截。
程序已把失败响应原文打印出来，按 Message 定位。

**Q5：Save 返回“字段不存在/不允许为空/基础资料不存在”？**
A：90% 是基础资料编号（FNumber）或字段 Key 与账套不符。先在 WebAPI 在线测试页用 View
查看一张已存在采购订单的真实数据包，对照字段 Key 和基础资料编号修正 Scenarios.cs/App.config。

**Q6：网上抄的插件代码 `import kd.bos.*` 能用吗？**
A：不能。那是**苍穹/星瀚（Java）**。星空（C#）命名空间是 `Kingdee.BOS.*`，
插件基类简单类名相同但语言、DLL、运行容器完全不同。

**Q7：可以在服务器上装 .NET Core/.NET 5+ 吗？**
A：经典星空不需要 .NET Core，官方部署 FAQ 明确提示误装可能导致 IIS 程序池异常；
二开工程请坚持 .NET Framework（4.5–4.8，随星空版本）。

**Q8：操作插件里写数据库和直接在表单插件里写 SQL 有什么区别？**
A：表单插件在界面进程执行、可被 WebAPI 绕过，且不在单据操作事务中；
`EndOperationTransaction` 在服务端数据库事务内执行，单据回滚则自定义逻辑一并回滚。
涉及数据一致性的写入必须放操作插件，并使用参数化 SQL（示例 `AuditLogHelper` 已示范）。

**Q9：生产环境部署有什么注意事项？**
A：① 先在同补丁版本的测试环境回归；② 备份账套库与管理库；③ 二开元数据走部署包、
DLL 逐台 APP 拷贝并记录版本；④ 标准补丁升级后必须回归全部插件；
⑤ 自定义表使用独立前缀（示例 `T_SKY_`），不要在金蝶标准表上加列/改列。

# Part D　卸载/回滚

1. BOS 设计器扩展中移除三个插件注册（或停用/删除扩展，恢复标准单据行为）；
2. 从站点 `bin` 删除 `KingdeeSky.Plugins.dll/.pdb`，回收应用程序池；
3. 审计表可保留或执行 `DROP TABLE dbo.T_SKY_AUDITLOG;`（确认不再需要后）；
4. WebAPI 客户端为绿色 EXE，直接删除目录即可，不在服务器写任何数据。

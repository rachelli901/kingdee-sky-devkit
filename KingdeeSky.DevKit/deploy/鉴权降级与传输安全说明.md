# 鉴权降级与传输安全说明

> 适用范围：`KingdeeSky.WebApiClient`（零金蝶 DLL 依赖的 WebAPI 客户端）。
> 目标：让三种鉴权模式在“未接真实星空环境”与“已接真实星空环境”两种状态下都有明确、可执行的行为，
> 避免把“未实现”误报成“凭据缺失”，并默认拒绝明文传输。

---

## 1. 三种鉴权模式（AuthMode）一览

| AuthMode | 实现类 | 状态 | 配置要点 | 降级指引 |
|---|---|---|---|---|
| `password` | `PasswordAuthProvider` | ✅ 可用（经典登录：账套 + 账号 + 密码） | `PasswordKey` 指向密钥源的密码键 | 默认模式，无需额外配置 |
| `oauth2` | `OAuth2AuthProvider` | ✅ 已实现 client_credentials 流程 | `TokenEndpoint` 令牌端点、`ClientIdKey`/`ClientSecretKey`、`Scope` | **前提**：星空环境确实提供 OAuth 令牌端点；无端点则降级 `password` 或 `appsec` |
| `appsec` | `AppIdAppSecAuthProvider` | 🟡 骨架可用（HMAC-SHA256 模板化） | `AppSecSigningTemplate` 签名模板、`AppIdKey`/`AppSecretKey` | 模板为空时抛 `NotSupportedException`（附降级指引），**不会**误报“凭据缺失” |

## 2. AppID/AppSec 签名制（appsec）骨架说明

### 2.1 为什么是“骨架”

金蝶云·星空原生第三方接入普遍采用 **AppID + AppSec 签名制**（主控台→【系统管理】→【系统管理】→【授权】→**第三方系统登录授权**）。
但不同版本/补丁的**签名字段、拼接顺序、时间戳格式、Nonce 规则**可能不同，且本仓库没有真实星空环境可核对，
因此实现为 **模板化签名器**：把“按规范拼待签串”这步抽成配置，接真实环境时只需把官方规范填进模板即可。

### 2.2 模板语法

`HmacSha256AppSecSigner` 支持占位符：`{appId}` `{appSecret}` `{timestamp}` `{nonce}` `{method}` `{path}` `{body}` `{bodyHash}` `{query}`。

示例（示意，非星空官方规范）：

```xml
<add key="AppSecSigningTemplate" value="{appId}|{appSecret}|{timestamp}|{nonce}|{method}|{path}|{bodyHash}" />
```

签名算法：`signature = HMAC-SHA256(appSecret, toSign)`，其中 `toSign` = 模板替换占位后的字符串（UTF-8）。
时间戳格式固定为 `yyyy-MM-dd HH:mm:ss`（UTC）；签名结果十六进制小写。

### 2.3 接入真实环境的核对清单

- [ ] 主控台【第三方系统登录授权】中确认 AppID/AppSec 的签发方式与有效期
- [ ] 拿到官方签名字段与拼接顺序，整理成 `AppSecSigningTemplate`
- [ ] 确认时间戳格式是否与本实现一致；不一致则需调整 `HmacSha256AppSecSigner` 的格式化串
- [ ] 确认签名头名称（默认 `X-Kingdee-Signature`）与时间戳/Nonce 头名称是否符合规范
- [ ] 用官方测试页或接口联调工具验证签名头被服务端接受

> 若星空环境**确实不提供** AppID/AppSec 签名制，直接使用 `AuthMode=password`（经典登录），
> 配合密钥分层（见下文）仍满足生产安全基线，不影响 L4 达成。

## 3. 传输安全开关（默认强制 HTTPS）

| 配置键 | 默认值（代码） | 说明 |
|---|---|---|
| `AllowInsecureHttp` | `false`（严格） | `true` 时放行明文 HTTP 并**每次请求输出告警**；`false` 时 http 地址在构造/请求前直接拒绝（fail-fast） |
| `AllowInvalidCertificate` | `false` | `true` 时放宽服务端证书校验（**仅限自签名/测试环境**，生产必须 `false`） |

行为说明：

1. **默认强制 HTTPS**：`EnsureUrlAllowed` 在客户端构造与每个请求前各校验一次；
   `http://` 地址在 `AllowInsecureHttp=false` 时抛 `InvalidOperationException`。
2. **显式放行才允许 http 并告警**：`AllowInsecureHttp=true` 时，放行且由 `SafeLogger.Warn` 输出明文传输告警。
3. **TLS 1.2 强制**：`Program.cs` 固定 `ServicePointManager.SecurityProtocol = Tls12`（移除 TLS 1.0/1.1 弱协议）。

> ⚠️ 仓库内 `App.config`（shipped 模板）将 `AllowInsecureHttp` 设为 `true` 并带醒目注释，
> 仅便于本地开发直连 mock/演示环境；**生产部署必须把 `AllowInsecureHttp` 改为 `false` 并改用 HTTPS 地址**。
> 部署后的第一道校验就是运行 `KingdeeSky.WebApiClient.exe --selfcheck`，其中传输安全策略段会给出 `WARN` 或失败。

## 4. 密钥分层（ISecretProvider 四实现）

| SecretStore | 实现类 | 适用场景 |
|---|---|---|
| `env` | `EnvironmentSecretProvider` | 开发机/CI 流水线：环境变量注入 |
| `file` | `FileSecretProvider` | 本地开发：`secrets.env`（不入库，`.gitignore` 排除） |
| `dpapi` | `DpapiSecretProvider` | **Windows 本地生产首选**：DPAPI + 服务账号隔离 |
| `kms` | `KmsSecretProvider` | 云端部署：外部 KMS/密钥管理服务 |

原则：`App.config` 只放**非敏感项与密钥键名**，密钥值一律经密钥源注入；
日志经 `SafeLogger` 自动脱敏（`SecretRedactor`）。

## 5. 常见问题（FAQ）

**Q1：运行报“不支持 AppID/AppSec 签名制鉴权尚未实现”？**
答：`AuthMode=appsec` 但 `AppSecSigningTemplate` 为空。按第 2.3 节配置模板；或改用 `AuthMode=password` / `oauth2`。

**Q2：生产环境如何确认不允许明文 HTTP？**
答：`--selfcheck` 输出中“传输安全策略”段：HTTPS 通过；HTTP+放行显示 `[WARN]`；HTTP+未放行显示失败。
同时检查 `App.config` 中 `AllowInsecureHttp=false`。

**Q3：星空真的没有 OAuth 令牌端点怎么办？**
答：不阻塞。使用 `AuthMode=password`（经典登录 + 密钥分层）或 `appsec`（若提供签名制）；`IAuthProvider` 抽象保持不变，后续可无缝切换。

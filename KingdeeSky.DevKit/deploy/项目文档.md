## 1. 项目定位

### 1.1 一句话定义

**KingdeeSky.DevKit 是一套面向「要把自己的系统接入金蝶云·星空」的集成商的参考工程**——它不是一套 ERP 系统，不替代金蝶运行时，而是把这四件难事一次性做成可复用的底座：

1. 端点调用封装（9 个 `.kdsvc` 端点，端点名难记且散落各处）
2. 认证与密钥治理（3 种鉴权 × 4 种密钥源，密码写进代码是行业常见事故）
3. 二开规范示范（关键规则放服务端校验插件，而非可被绕过的界面插件）
4. 交付工程化（测试、CI 门禁、部署与回滚文档、密钥扫描）

### 1.2 目标读者与典型用法

| 角色 | 能拿到什么 |
|---|---|
| ERP 集成商开发者 | 复制 `KingdeeWebApiClient` 到自己解决方案，改配置即接入；照抄 `KingdeeSky.Plugins` 的插件写法 |
| 客户方 IT / 实施顾问 | 浏览器操作台（免安装）验证接口连通性；部署文档指导上线 |
| 项目负责人 | 交付物清单、CI 门禁、回滚预案、安全审计清单 |
| 学习二开者 | 一条渐进路线：标准单据 → 自定义单据 → 下推转换与反写 |

**典型接入流程**：

```
改配置（站点地址 + 账套 + 账号） → 复制客户端封装到自己系统 → 需要二开则照插件范例改
→ 联调期用本地 mock 自测 → 真实环境联调 → 上线
```

### 1.3 明确不是什么 `[代码]`

| 它**不是** | 它**是** |
|---|---|
| ERP 系统 | 接入 ERP 的**那一层** |
| 替代金蝶星空的产品 | 星空的**对接参考包**（非官方） |
| 含业务逻辑的业务系统 | 通用底座；业务逻辑留给集成商实现 |
| 可独立运行的完整应用 | 需配真实星空环境才有意义 |
| SDK（会随补丁演进） | 自主编写的固定版本代码，行为可预测 |

### 1.4 版本与兼容性 `[代码]`

| 项 | 值 | 依据 |
|---|---|---|
| 目标框架 | .NET Framework 4.8 | `src/KingdeeSky.WebApiClient/KingdeeSky.WebApiClient.csproj:11` |
| 适用星空版本 | 经典星空（K/3 Cloud）V6 – V9 | `README.md` 定位声明 |
| 客户端第三方依赖 | **0 个**（仅 `System` / `System.Web.Extensions` 等原生程序集） | `KingdeeSky.WebApiClient.csproj` References 段 |
| 插件工程依赖 | 金蝶 BOS 程序集 4 个（`Kingdee.BOS` / `.Core` / `.App` / `.Orm`） | `src/KingdeeSky.Plugins/KingdeeSky.Plugins.csproj` |
| 源码规模 | `src` 32 个 `.cs`（客户端 21 + 插件 11） | 本机统计 |

> **为什么锁定 .NET Framework 4.8 而非 .NET 9/10**
> 二开插件必须与宿主（星空 V9.1 服务端插件运行时）**同 CLR 版本加载**，这是硬约束，不能为「用新框架」而偏离。
> 客户端为兼容更多存量 .NET FX 应用同样收敛到 4.8。
> **这是与目标运行平台对齐的工程决策，不是技术债。**

### 4.2 三个关键抽象

**① `IApiTransport` —— 让鉴权层复用传输层**

```csharp
public interface IApiTransport
{
    string PostJson(string pathOrUrl, string jsonBody);
    string PostForm(string pathOrUrl, IDictionary<string, string> form);
    void UseBearerToken(string token);
    void SetRequestHeader(string name, string value);
}
```

鉴权实现不需要自己发 HTTP 请求 —— OAuth2 要取令牌（表单 POST + Bearer）、AppSec 要附加签名头，都通过这个接口复用客户端已有的传输、Cookie 会话与传输安全策略。

**② `IAuthProvider` —— 鉴权可插拔**

```csharp
public interface IAuthProvider
{
    string Name { get; }
    LoginResult Authenticate(IApiTransport transport, AuthContext context);
}
```

`AuthProviderFactory.Create(mode, template, timestampFormat)` 按配置返回实现，**业务代码完全不感知用的是哪种鉴权**。

**③ `ISecretProvider` —— 密钥来源可插拔**

```csharp
public interface ISecretProvider
{
    string Name { get; }
    bool TryGet(string key, out string value);
}
```

### 4.3 一次调用的完整数据流

```
业务代码
  → client.Save(formId, model)
  → _json.Serialize(model)                    序列化数据包
  → FormAction(SvcSave, formId, dataJson)     组装 {formid, data}
  → ValidateFormId(formId)                    fail-fast 入参校验
  → Post(service, payload)
  → PostJson → CreateRequest
      ├─ TransportSecurityPolicy.EnsureUrlAllowed(url, ...)   每个请求都过传输策略
      ├─ 附加 Bearer 令牌（如有）
      ├─ 附加自定义请求头（AppSec 签名 / 时间戳 / Nonce）
      └─ CookieContainer 维持会话
  → ReadResponseOrThrow
      ├─ 成功：返回响应正文
      └─ 失败：读出响应体 → _logger.Scrub(responseText) 脱敏 → 抛 InvalidOperationException
```

## 5. 客户端 API 参考

### 5.1 构造与生命周期 `[代码]`

```csharp
public KingdeeWebApiClient(
    string serverUrl,          // 站点地址，如 https://xxx.kdcloud.com/
    string acctId,             // 数据中心（账套）ID
    IAuthProvider authProvider,
    AuthContext authContext,
    SafeLogger logger,
    bool allowInsecureHttp = false)   // 默认强制 HTTPS
```

构造即校验：`ServerUrl` / `AcctId` 为空抛 `ArgumentException`；`authProvider` / `authContext` 为 null 抛 `ArgumentNullException`；`serverUrl` 经 `TransportSecurityPolicy.EnsureUrlAllowed` 校验传输通道。

**`Dispose()` 的真实职责** `[代码]`（`KingdeeWebApiClient.cs:509-533`）：

本类型**不持有非托管句柄、长连接或流** —— 每次请求都是独立的 `HttpWebRequest`，随响应结束即释放；`CookieContainer` 随进程自行失效。因此 `Dispose` 的实际职责是**清理凭据类内存副本**：

```csharp
_bearerToken = null;      // Bearer 令牌
_extraHeaders.Clear();    // AppSec 签名 / 时间戳 / Nonce
```

避免已交付或已弃用的实例继续持有**可用于冒充的凭据材料**。释放后再调用任何方法会抛 `ObjectDisposedException`。

### 5.2 业务方法

| 方法 | 签名 | 说明 |
|---|---|---|
| `Login()` | `LoginResult` | 委托当前鉴权实现完成，成功后维持会话 |
| `Save` | `string Save(string formId, object model)` | 保存（新增/修改），`model` 内部序列化为 `data` JSON 字符串 |
| `Submit` | `string Submit(string formId, IList<long> ids)` | 提交单据 |
| `Audit` | `string Audit(string formId, IList<long> ids)` | 审核单据 |
| `UnAudit` | `string UnAudit(string formId, IList<long> ids)` | 反审核单据 |
| `Delete` | `string Delete(string formId, IList<long> ids)` | 删除（**仅草稿/已提交可删，已审核需先反审核**） |
| `Push` | `string Push(string formId, object pushParam)` | 下推（单据转换） |
| `View` | `string View(string formId, long pkId, long createOrgId = 0)` | 按内码查看完整数据包 |
| `ExecuteBillQuery` | `object[][] ExecuteBillQuery(string formId, string fieldKeys, string filterString, string orderString, int topRowCount = 0, int startRow = 0, int limit = 0)` | 动态表单查询，返回二维数组 |
| `Invoke` | `string Invoke(string serviceName, object payload)` | 调用任意 `.kdsvc` 端点 |

> 除 `Invoke` 与 `Login` 外，所有业务方法返回**原始响应 JSON 字符串**。用静态方法 `KingdeeWebApiClient.InspectResult(rawJson)` 解析为 `ApiCallResult`。

### 5.3.1 请求信封与两个必踩的坑 `[实测]`

所有业务端点都是同一个信封：

```
POST /K3Cloud/{Service}.common.kdsvc   HTTP/1.1
Content-Type: application/json; charset=utf-8
（登录后带 Cookie；appsec 方式追加 X-Kingdee-Signature / Timestamp / Nonce）

{ "formid": "PUR_PurchaseOrder", "data": "<JSON 字符串>" }
```

> **坑一：`data` 是字符串，不是对象。**
> 先把 model 序列化成 JSON **字符串**再塞进 `data`（客户端 `FormAction` 就是这么做的）。

> **坑二：`Save` 的 data 顶层要套 `Model`，`Submit`/`Audit` 不能套。**
> - `Save` → `data` = `{"Model": {...}, "NeedUpDateFields": [...]}`
> - `Submit`/`Audit` → `data` = `{"Ids": "1,2"}` 或 `{"Numbers": ["PO..."]}`，**不要套 `Model`**
>
> 套错会直接报「**编码值或内码值必须传其一**」—— 这是对接星空最常见的首个坑。

### 5.3.2 单据状态与可否操作 `[实测]`

| 值 | 含义 | 提交 | 审核 | 删除 |
|---|---|---|---|---|
| `Z` | 暂存草稿 | ✔ | ✘ | ✔ |
| `A` | 创建（已保存） | ✔ | ✔ | ✔ |
| `B` | 审核中 / 已提交 | ✘ | ✔ | ✔ |
| `C` | **已审核（终态）** | ✘ | ✘ | ✘（须先反审核） |
| `D` | 重新审核 | 按单据配置，通常走反审核链路 | | |

> 客户端 `Delete` 在服务端同样受此约束 —— 已审核单据必须先 `UnAudit` 回 `B` 才能删。

### 5.3.3 返回结构与日期字段 `[代码]`

统一外壳：

```json
{ "Result": { "ResponseStatus": { "IsSuccess": true, "Msg": "...", "Errors": [] },
              "SuccessEntitys": [ { "Id": 123, "Number": "PO001" } ] } }
```

**日期字段有两种形态**，都要能处理：

| 形态 | 出现位置 | 处理方式 |
|---|---|---|
| `/Date(1760726400000)/` | JSON 里的日期 | `JavaScriptSerializer` 反序列化时**已自动转成 `DateTime`**（`Scenarios.Cell` 靠 `as DateTime?` 命中） |
| 纯字符串 `"2026-10-18"` | 版本差异 / 直接给字符串的字段 | 需自行格式化 |

> **查询结果按位置取**：`ExecuteBillQuery` 返回二维数组，**每行按 `fieldKeys` 的顺序排列**，不是对象数组。要按 `fieldKeys` 顺序逐列映射。

### 5.4 入参校验规则 `[代码]`

校验在**请求发出之前**完成（fail-fast），不产生无效网络往返：

| 校验 | 规则 | 触发异常 |
|---|---|---|
| `FormId` 非空 | 不可为 null / 空 / 空白 | `ArgumentException("单据 FormId 不能为空")` |
| `ids` 集合非空 | 不可为 null / 空集合 | `ArgumentException("单据内码集合不能为空")` |
| `ids` 值有效 | 每个必须 > 0 | `ArgumentException("单据内码必须为正数")` |
| `ids` 无重复 | 集合内不得含重复值 | `ArgumentException("单据内码集合不能包含重复值")` |
| `fieldKeys` 非空 | 查询字段不能为空 | `ArgumentException("查询字段不能为空")` |
| 分页参数非负 | `topRowCount` / `startRow` / `limit` ≥ 0 | `ArgumentOutOfRangeException` |

> 「重复 id 拦截」是易漏点：同一内码重复提交会被星空侧行为不一致地处理，客户端提前拒绝更可控。

### 5.5 请求头保护 `[代码]`

`SetRequestHeader` 会**主动拒绝**以下由传输层管理的头（否则 `HttpWebRequest` 会抛平台相关的 `ProtocolViolationException`）：

`Authorization` / `Content-Type` / `Content-Length` / `Host` / `Connection`

自定义头（如 AppSec 签名）走这个接口，键名大小写不敏感。

### 5.6 响应解析 `[代码]`

```csharp
public static ApiCallResult InspectResult(string rawJson)
```

解析金蝶标准结构：

```
Result
├── ResponseStatus
│   ├── IsSuccess  → ApiCallResult.IsSuccess
│   ├── Msg         → ApiCallResult.Message（无 Errors 时）
│   └── Errors[]    → ApiCallResult.Errors（多条以 "; " 连接）
└── SuccessEntitys[]
    ├── Id          → ApiCallResult.Ids
    └── Number      → ApiCallResult.Numbers
```

容错：返回非合法 JSON → `IsSuccess=false`，`Message="返回内容不是合法 JSON：..."`（截断 500 字符）；缺 `Result` 节点 → 明确提示而非抛异常。

## 6. 鉴权体系

### 6.1 三种鉴权 `[代码]`

`AuthProviderFactory.Create(mode, appSecSigningTemplate, appSecTimestampFormat)`：

| `AuthMode` | 实现类 | 机制 | 必需配置 |
|---|---|---|---|
| `password`（默认） | `PasswordAuthProvider` | 账套 + 用户名 + 密码，Cookie 会话 | `AcctId` / `UserName` / 密码密钥 |
| `oauth2` | `OAuth2AuthProvider` | OAuth 2.0 client_credentials，取令牌后 Bearer | `TokenEndpoint`（必需）/ `Scope` / 客户端密钥 |
| `appsec` | `AppIdAppSecAuthProvider` | AppID + AppSecret HMAC-SHA256 签名 | `AppSecSigningTemplate`（必需） |

别名：`oauth` ≡ `oauth2`；`appid_appsec` ≡ `appsec`。未知模式抛 `ArgumentException` 并列出可选值。

### 6.2 配置校验的 fail-fast 设计 `[代码]`

`Settings.ValidateOrThrow()`（`Scenarios.cs:156-191`）在**启动时**而非首次调用时拒绝错误配置：

- `AcctId` 仍为「请填写」占位 → 直接拒绝，提示用环境变量/密钥文件/DPAPI/KMS 提供密码
- `AuthMode=oauth2` 但未配 `TokenEndpoint` → 拒绝，并强制该端点走 HTTPS 校验
- `AuthMode=appsec` 但未配 `AppSecSigningTemplate` → 拒绝，提示仍是占位实现
- **`DeployEnv=prod` 且 `AllowInsecureHttp=true` → 拒绝**（生产环境禁止明文 HTTP）

> **设计要点**：把「启动后第一次登录才失败」的问题提前到启动瞬间暴露。配置错误在部署阶段就暴露，而不是在客户第一次点按钮时。

### 6.3 AppSec 签名器 `[代码]`

`HmacSha256AppSecSigner`（`Security/HmacSha256AppSecSigner.cs`）是**完整实现**，非占位。

**模板占位符（9 个）**：

| 占位符 | 含义 |
|---|---|
| `{appId}` | AppID |
| `{appSecret}` | AppSecret |
| `{timestamp}` | 时间戳 |
| `{nonce}` | 随机串（默认 GUID 32 位） |
| `{method}` | HTTP 方法（默认 POST） |
| `{path}` | 请求路径 |
| `{body}` | 请求体原文 |
| `{bodyHash}` | 请求体 SHA-256 十六进制 |
| `{query}` | 查询串 |

**时间戳格式**（`AppSecTimestampFormat`）：

| 值 | 输出 |
|---|---|
| 留空 | `yyyy-MM-dd HH:mm:ss`（默认） |
| `unix` | Unix 秒整数戳 |
| `unix-ms` | Unix 毫秒整数戳 |
| 其他 | 自定义 .NET 格式串 |

**时间戳一律用 `CultureInfo.InvariantCulture`** —— 避免不同区域设置产生格式差异，这是签名校验失败的高频原因。

**请求头**：签名写入 `X-Kingdee-Signature`，同时携带 `Timestamp` 与 `Nonce`。

> ⚠️ **接入真实环境时，签名字段与拼接顺序必须以星空【第三方系统登录授权】的在线测试样本对齐，不能凭猜。** 本工程提供的是可配置的模板化机制，协议细节以目标账套规范为准。

**未配置模板时的行为**：签名器抛 `NotSupportedException`，并给出「配置模板或改用 password/oauth2」的降级指引 —— 避免把「未实现」误报为「凭据缺失」。

### 7.1 正交解耦设计 `[代码]`

### 7.2 密钥键名映射 `[代码]`

### 7.3 日志脱敏 `[代码]`

`SecretRedactor`（`Security/SecretRedactor.cs`）采用**双策略**，按密钥长度分流：

| 密钥长度 | 策略 | 理由 |
|---|---|---|
| ≥ 4 字符 | 全局子串替换 → `***REDACTED***` | 长密钥唯一性高，全局替换安全 |
| < 4 字符 | **整词**替换（两侧为非单词字符） | 短口令若全局替换会误伤日志中随处可见的短串；整词替换既能掩掉以独立词出现的弱口令，又不误伤嵌在普通单词里的片段 |

`SafeLogger.Scrub(text)` 是日志器与异常消息的统一脱敏入口 —— 异常响应体在抛出前先脱敏（`KingdeeWebApiClient.cs:393`）。

**短掩码展示**：`MaskShort(value)` 首尾各留 2 字符（`ab****yz`），不足 5 字符则整串打码。

## 8. 传输安全

### 8.1 传输通道策略 `[代码]`

`TransportSecurityPolicy.EnsureUrlAllowed(url, allowInsecureHttp, logger, label)`：

| 协议 | 行为 |
|---|---|
| `https` | 直接放行 |
| `http` + `allowInsecureHttp=true` | 放行 + **输出告警**（提示生产必须关闭） |
| `http` + `allowInsecureHttp=false` | **拒绝**，抛 `InvalidOperationException` |
| 其他协议 | 抛 `ArgumentException`（仅支持 http/https） |

**调用点覆盖两处** `[代码]`：

1. 客户端构造时校验 `ServerUrl`（`KingdeeWebApiClient.cs:96`）
2. **每个请求**发送前校验实际 URL（`KingdeeWebApiClient.cs:346`）

> 第 2 点很关键：只在构造时校验不够 —— 若 `ServerUrl` 是 https 但某次调用传入绝对 http URL，仍须拦截。

### 8.2 证书校验 `[代码]`

`AllowInvalidCertificate` 语义：

- `false`（默认）= 完整校验服务器证书链
- `true` = **仅对回环地址（127.0.0.1 / localhost）放行**，并把真实证书链错误打印出来；**其余主机仍按默认策略拒绝**

这个收窄很关键 —— 早期实现是「全局放行」，等于给任意主机开后门；现在只有本地开发场景能用到这个开关。

### 8.3 开关解析 `[代码]`

`TransportSecurityPolicy.ParseFlag(value, defaultValue)` 接受 `1/true/yes/on` 与 `0/false/no/off`（大小写不敏感）；**无法识别时回退默认值（默认严格）**。

> 宁可严格也不猜 —— 配置写错时应当失败，而不是静默降级。

### 9.2 二开铁律 `[代码]`

> **表单插件只在当前用户的界面上生效，可被绕过（如 WebAPI 保存）；校验插件在服务端执行，界面端与 WebAPI 端的保存都会被拦截。**

这条是本工程最核心的二开认知。实践含义：

| 规则类型 | 应放位置 | 原因 |
|---|---|---|
| 交互体验（默认值、联动计算、按钮拦截） | 表单插件 | 只影响界面体验，绕过无害 |
| **业务约束**（数量 > 0、日期不得早于今天、必填兜底） | **校验插件** | 必须服务端强制，WebAPI 同样拦截 |

2. 采购数量必须 > 0
3. 需求日期若填写，不得早于当天

错误通过 `AddErrorField(EntityKey, i, fieldKey, message)` 收集 —— **精确到行与字段**，用户能直接知道改哪一格。

### 9.3 元数据取值：不要硬编码 ORM 属性名 `[代码]`

`FieldHelper`（`Plugins/Common/FieldHelper.cs`）提供三种安全取值：

```csharp
// 1. 取分录集合
DynamicObjectCollection entry = FieldHelper.GetEntry(dataEntity, biz, "FEntity");

// 2. 按字段 Key 取标量（自动类型转换，失败回退默认值）
decimal qty = FieldHelper.GetValue<decimal>(row, biz, "FQty");

// 3. 取基础资料字段对象（再用 ["Number"] / ["Name"] 取编号名称）
DynamicObject material = FieldHelper.GetBaseData(row, biz, "FMaterialId");
```

**为什么不直接写 ORM 属性名**：ORM 属性名通常是字段 Key 去掉首字母 `F`（`FQty` → `Qty`），**但并非每个字段都严格遵守该规则**。通过 `BusinessInfo` 元数据对象索引 `DynamicObject` 最稳妥 —— 字段不存在时 `GetField` 返回 null，取值方法直接回退默认值，不会抛异常。

`GetValue<T>` 的容错：null / `DBNull.Value` → 默认值；类型不匹配 → `Convert.ChangeType`；转换失败 → 捕获异常回退默认值。**取不到值不是崩溃理由**。

### 9.4 跨版本兼容性处理 `[代码]`

`PurchaseOrderFormPlugin.IsChangedField` 展示了插件开发中常见的**版本差异**处理：

```csharp
// e.Field.Key 对分录字段可能返回短键（FQty），
// 也可能返回带实体限定的内部标识（FEntity_FQty / FEntity.FQty）
// → 两种形态一并比较，带前缀时按末段比对
return key.EndsWith("_" + fieldKey, StringComparison.OrdinalIgnoreCase)
    || key.EndsWith("." + fieldKey, StringComparison.OrdinalIgnoreCase);
```

同样地，`DataChanged` 中**不用「行号 < 0」做前置拦截** —— 表头字段的 `e.Row` 在不同补丁版本下可能为 0 也可能为 -1，用行号判定既会漏掉分录事件、又拦不住表头事件；**字段标识才是稳定的判定依据**。

> 代码注释里明确写了这处判定「需在真实星空环境用一次界面操作回归确认」—— **诚实标注了未经真实环境验证的部分**。

### 9.5 审计日志与事务同生共死 `[代码]`

`AuditLogHelper.WriteOperationLog` 把审核动作写入自定义表 `dbo.T_SKY_AUDITLOG`（建表脚本 `deploy/Scripts/T_SKY_AUDITLOG.sql`）。

**三个关键设计**：

1. **参数化 SQL** —— 用 `SqlParam` + `KDDbType` 传参，防止单据编号含单引号导致注入 / 语法错误
2. **事务内调用** —— 设计为在操作插件的 `EndOperationTransaction`（数据库事务内）调用，与单据审核**同生共死**：审核回滚，审计记录一并回滚
3. **`GETDATE()` 由数据库取** —— 时间戳以数据库为准，避免应用服务器时钟漂移导致审计时间不可信

### 9.6 单据转换插件要点 `[代码]`

`PurchaseOrderToInStockConvertPlugin` 演示 `AfterConvert` 钩子：

- **`AfterConvert` 是转换插件中最常用的钩子** —— 目标单数据包全部字段映射、分录生成完毕后执行
- **值更新事件在下推过程中不会触发** —— 映射规则带不出的字段通常都要在这里补
- 通过 `head[entryEntity.DynamicProperty]` 索引数据包，避免硬编码 ORM 属性名

其他常用钩子（按需重写）：`OnQueryBuilderParemeter`（注意官方拼写是 `Paremeter`）、`OnFieldMapping` / `AfterFieldMapping`、`OnCreateTargetBill` / `AfterCreateTargetBill`。

## 11. 构建与发布

### 11.1 四段门禁 `[代码]`

`eng/build.ps1` 的执行序列：

```
[0/4] Secret scan     → eng/scan-secrets.ps1（明文密钥扫描）
[1/4] Compiling       → csc /optimize+ /debug-（Release）
[2/4] Running test gate → 81 条用例，失败即中断
[3/4] Packaging       → staging → zip → SHA-256 sidecar
```

**任一环失败即终止**，不会产出半成品包。

### 11.2 密钥扫描器 `[代码]`

`eng/scan-secrets.ps1` 的规则设计：

| 规则 | 说明 |
|---|---|
| 4 条模式 | 匹配 `password` / `secret` / `token` / `apikey` 等键名 |
| 3 条赋值规则 | 引号赋值、裸值赋值、XML `<add key= value=>` |
| 值白名单 | `ALL_CAPS` 变量名、`${...}` 占位、`CHANGE_ME` / `PLACEHOLDER` / `YOUR_` / `example` 等 |
| **大小写敏感** | ALL_CAPS 检查**故意用大小写敏感** —— 避免 `demo123` 这类小写口令漏过 |

扫描范围是**仓库根**（不是 DevKit 子目录），覆盖全部跟踪文件。

### 11.3 产物与校验 `[代码]`

| 项 | 规则 |
|---|---|
| 产物路径 | `KingdeeSky.DevKit/artifacts/KingdeeSky.DevKit-<version>-<timestamp>.zip` |
| 校验文件 | 同名 `.sha256` sidecar，`sha256sum` 标准双空格格式，`-Encoding ASCII` |
| **生成后自校验** | 写完立即回读比对，不一致则构建失败 |
| **保留策略** | `-KeepArtifacts` 参数（默认 5），保留最近 5 个包 |
| 排序依据 | **文件名内嵌时间戳**，而非版本号字典序（`1.0.10 < 1.0.9` 会排错）或 mtime（会被复制改写） |
| 成对处理 | zip 与 sidecar 必须成对删除，不留孤儿 |
| 缺失补齐 | 保留的包若缺 sidecar，自动按字节哈希补建 |

> 清理动作挂在 **sidecar 自校验通过之后** —— 构建失败时绝不误删历史包。

### 11.4 CI 流水线 `[代码]`

`.github/workflows/ci.yml`（**位于仓库根**）：

| 步骤 | 作用 |
|---|---|
| 1. Secret scan | 全仓库明文密钥扫描 |
| 2. Build, test and package | `build.ps1 -SkipSecretScan`（扫描已在步骤 1 做过） |
| 3. Run numbered regression cases | `run-cases.ps1 -All` |
| 4. **Verify package carries the delivered HTML** | 解包比对包内 HTML 与 `deploy/` 源文件 SHA-256，**漂移即 fail** |
| 5. Verify package SHA-256 sidecars | 校验每个包的 sidecar |
| 6. Upload package | 上传 zip + sidecar |

> **为什么 CI 必须在仓库根** `[代码]`：GitHub Actions 只读仓库根的 `.github/workflows/`，放在 `KingdeeSky.DevKit/` 下的副本**永远不会触发**。这是本工程踩过的坑，注释里明确写了下来。

`CONTRIBUTING.md` 第 5 节定义了发布契约：版本号单一事实源在 `eng/version.txt`；发布用 `git tag -a vX.Y.Z`。

## 15. 扩展指南

### 15.1 扩展一个业务场景

在 `Scenarios.cs` 中新增静态方法即可，无需改动客户端核心：

```csharp
public static void CreateSalesOrder(KingdeeWebApiClient client, Settings s)
{
    var model = new Dictionary<string, object> { /* ... */ };
    string raw = client.Save("SAL_SaleOrder", model);
    var result = KingdeeWebApiClient.InspectResult(raw);
    if (!result.IsSuccess) { Console.WriteLine("保存失败：{0}", result.Message); return; }
}
```

### 15.2 扩展一个端点

两种方式：

**① 若属于标准 DynamicFormService 系列** —— 在 `KingdeeWebApiClient` 中加常量 + 公开方法，复用 `FormAction`：

```csharp
private const string SvcXxx = "Kingdee.BOS.WebApi.ServicesStub.DynamicFormService.Xxx.common.kdsvc";

public string Xxx(string formId, object param)
{
    return FormAction(SvcXxx, formId, _json.Serialize(param));
}
```

**② 标准服务未覆盖** —— 直接用 `Invoke(serviceName, payload)`，无需改代码。

### 15.3 扩展一种鉴权方式

1. 实现 `IAuthProvider`：

```csharp
public class MyAuthProvider : IAuthProvider
{
    public string Name { get { return "my-auth"; } }

    public LoginResult Authenticate(IApiTransport transport, AuthContext context)
    {
        // 从 context.Secrets 取密钥（不要自行读配置文件）
        // 通过 transport.PostJson / PostForm / SetRequestHeader 发起请求
    }
}
```

2. 在 `AuthProviderFactory.Create` 的 `switch` 中加分支。

### 15.4 扩展一种密钥源

1. 实现 `ISecretProvider`：

```csharp
public class MySecretProvider : ISecretProvider
{
    public string Name { get { return "my-store"; } }
    public bool TryGet(string key, out string value) { /* ... */ }
}
```

2. 在 `SecretProviderFactory.Create` 的 `switch` 中加分支，并在 `App.config` 加对应选项。

> **务必**：新密钥源实现后，**把密钥加入 `SafeLogger` 的脱敏登记**，否则密钥可能出现在日志里。

### 15.5 扩展一个二开插件

1. 在 `src/KingdeeSky.Plugins/` 下新建类，继承对应基类（`AbstractBillPlugIn` / `AbstractValidator` / `AbstractConvertPlugIn` / 操作插件基类）；
2. 用 `FieldHelper` 取值，不要硬编码 ORM 属性名；
3. 加 `[HotUpdate]` 特性（需站点 `Common.config` 启用 `IsEnablePlugInHotUpdate`，且**仅 1 小时内更新的 DLL 生效，首次部署仍需重启 / 回收**）；
4. 在类注释里写清**注册位置**与**类名完整格式**；
5. 在 `deploy/单据转换与反写插件指南.md` 或相应文档中补充说明。

### 16.2 Plugins 工程的编译依赖 `[实测]`

`KingdeeSky.Plugins` 引用 4 个金蝶 BOS 程序集（`HintPath` 指向 `lib/`），而 **`lib/` 里只有获取脚本、没有 DLL** —— 这些程序集只存在于**已授权的星空服务器**上，**不随代码分发**（合规要求）。

**这不是代码缺陷，而是外部依赖的客观边界。** 本工程对此做了三层处理，把「缺依赖」从**噪音**变成**指引**：

| 层 | 做法 | 效果 |
|---|---|---|
| 解决方案层 | `KingdeeSky.DevKit.sln` 中 Plugins **不参与默认构建**（保留 `ActiveCfg`、去掉 `Build.0`） | VS 里「生成解决方案」→ **0 错误**；工程仍在解决方案资源管理器中可见、可读、可单独生成 |
| 工程层 | `KingdeeSky.Plugins.csproj` 增加前置检查 Target（`CheckKingdeeBinsPresent`），在 `ResolveAssemblyReferences` 之前判定 DLL 是否存在 | 缺 DLL 时给出**一条带错误码 `KDSKY1001` 的可执行指引**（含两种解决路径），替代原先 **101 条 `CS0246` 类型缺失噪音** |
| 构建层 | `eng/build.ps1` 以 `lib\Kingdee.BOS.Core.dll` 为探针 | 无 DLL → 输出 Warning 并自动跳过 Plugins；**不影响客户端与测试的构建打包** |

**指引文案在缺 DLL 时的实际输出**：

```
error KDSKY1001: 缺少金蝶 BOS 程序集，无法编译 KingdeeSky.Plugins（当前目录：..\..\lib）。

处理方式（二选一）：
1) 若你拥有授权的星空应用服务器：运行 lib\copy-kingdee-dlls.bat，按提示粘贴站点 WebSite\bin 路径，自动复制 4 个 DLL 到 lib\；
2) 若 DLL 已在别处：直接用属性覆盖，无需改动工程文件，
   msbuild KingdeeSky.Plugins.csproj /p:KingdeeBinsDir="D:\K3Cloud\WebSite\bin"

说明：Kingdee.BOS.* 属金蝶商业软件，受许可协议保护，不能随本仓库分发。
仅编译客户端不需要这一步：KingdeeSky.WebApiClient 与 KingdeeSky.WebApiClient.Tests 均可零金蝶依赖编译。
```

> **前置检查只判定文件是否存在，不加载程序集** —— 因此不需要授权环境也能给出正确结论；DLL 就位时检查自动放行，不会误拦截（已实测验证）。

**解决方式**：从已授权的星空应用服务器执行 `lib/copy-kingdee-dlls.bat`，把 4 个 DLL 拷进 `lib/`；或在有 DLL 的机器上用 `msbuild /p:KingdeeBinsDir=...` 指定路径。

### 16.3 其他边界

- **目标客户是 Windows** —— .NET FX 4.8 EXE；`Compress-Archive` 在 Windows 上把 zip 条目名存为反斜杠（`deploy\file.html`），Linux 解压可能受影响
- **mock 是协议级模拟** —— 不是真实金蝶环境，业务逻辑与真实星空有差异
- **性能基线来自本地桩** —— 不代表生产性能

## 17. FAQ

### 17.1 启动类问题

**Q：启动报 `404 Not Found`，且 IIS 返回了详细错误页**

A：请求打到了本机 IIS 的 80 端口，而不是 mock 的 18080。检查 `App.config` 的 `ServerUrl` **是否带 `:18080`**，改完重新生成（VS 只在生成时把 `App.config` 拷成 `bin\<Config>\*.exe.config`）。

**Q：自检报 `AcctId` 相关失败**

A：`AcctId` 仍是「请填写账套ID」占位文字。`Settings.ValidateOrThrow()` 会拒绝启动。改成真实账套 ID（演示可用 `demo`）。

**Q：自检报密钥源相关失败**

A：`SecretStore=env` 但环境变量未设置。自检会**校验密钥实际存在**，不只是「密钥源可构造」。用 `setx KINGDEE_PASSWORD <密码>` 配置（注意 `setx` 只对**新启动的进程**生效，VS 需完全重启）。

**Q：VS 编译报 `CS0246: 找不到 "IAppSecSigner"`**

A：csproj 的 `<Compile Include>` 清单漏登记了新增文件。VS 按清单编译，命令行脚本（递归抓全部 `.cs`）不受影响 —— **两条构建路径不一致**。解决：把缺失文件补进 csproj 并重新生成。

**Q：`生成解决方案` 报 101 个错误**

A：现在**不会了** —— 解决方案默认不构建 `KingdeeSky.Plugins`（它需要授权环境才能编译），「生成解决方案」是 0 错误。

若你确实要编译插件（右键 Plugins →「生成」），会看到**一条 `KDSKY1001` 指引**（不再是 101 条 `CS0246` 噪音），里面写明了两条处理路径：跑 `lib\copy-kingdee-dlls.bat` 拷贝 DLL，或用 `msbuild /p:KingdeeBinsDir=...` 指定已有 DLL 的位置。详见 §16.2。

### 17.2 使用类问题

**Q：单据状态 A / B / C 分别是什么？**

A：`A` = 暂存（草稿）、`B` = 已提交、`C` = 已审核。删除仅允许非 `C` 状态的单据。

**Q：`ExecuteBillQuery` 返回的日期为什么变成了 `2026-10-23` 格式？**

A：星空日期在 JSON 中为 `/Date(毫秒)/`，`JavaScriptSerializer` 自动转成了 `DateTime`，示例代码再格式化为 `yyyy-MM-dd`。

**Q：如何调一个本文档未覆盖的端点？**

A：用 `client.Invoke(serviceName, payload)`。端点定义见主控台【公共设置 → 动态服务定义 → WebAPI】。

**Q：为什么不用 Newtonsoft.Json？**

A：刻意保持**零第三方依赖**，以兼容存量 .NET FX 环境并保证可审计性。代价是 JSON / HTTP 均手写封装。`JavaScriptSerializer` 上限已调到 64 MB。

### 17.3 工程类问题

**Q：改了 `prototype/index.html`，`deploy/` 里的操作台没变？**

A：现在不会了 —— `build-single-file.mjs` 构建后**自动同步**到 `deploy/KingdeeSky.WebApiClient.html`。以前是手工复制，是已知的漂移来源。

**Q：CI 里 `Verify package carries the delivered HTML` 报「包内缺交付物」，但文件明明在？**

A：**zip 条目名分隔符问题**。`Compress-Archive` 在 Windows 上把条目名存成反斜杠（`deploy\file.html`），而 Python 的 `zipfile` 读取时会归一化成正斜杠显示 —— 两边看到的名字不一样。CI 校验已改为**归一化后比较**。

**Q：递归抓全部 `.cs` 编译会报 `CS0017`（多个 Main）**

A：`Program.cs`（客户端入口）与 `TestProgram.cs`（测试入口）冲突。测试工程必须**显式排除 `Program.cs`**。这条约束已写入 `CONTRIBUTING.md` §6.1。

**Q：`artifacts/` 里为什么只有 5 个包？**

A：构建时自动保留最近 5 个（`-KeepArtifacts` 可调，传 `0` 不清理）。历史包已被 gitignore，不在版本控制内。

### 17.4 定位路径速查

| 现象 | 先查 |
|---|---|
| 登录失败 | `AuthMode` / 密钥源配置 / `ServerUrl` 端口 / 账套 ID |
| 保存成功但状态没变 | 是否真的调用了 `Submit` / `Audit`；查 `Result.ResponseStatus.IsSuccess` |
| 自检与实际行为不一致 | 自检读的是 `bin\<Config>\*.exe.config`，确认它是最新的 |
| 插件不生效 | 转换规则是否**停用再启用**一次；DLL 是否已复制到 `lib/` |
| 门禁突然失败 | 先跑 `.\build.bat` 看是哪一段（扫描/编译/测试/打包） |

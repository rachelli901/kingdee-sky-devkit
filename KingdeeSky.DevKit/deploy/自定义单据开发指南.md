# 自定义单据从零搭建指南（示例：差旅费报销单 SKY_ExpReimburse）

> 目标：不依赖任何标准单据，在 BOS 设计器中**从零新建一张业务单据**，挂上本代码包
> `KingdeeSky.Plugins.CustomBill` 下的三个插件，并能用 WebAPI 读写。
> 适用经典星空（企业版/标准版）BOS 集成开发平台；不同补丁版本菜单措辞略有差异。

---

## 1. 核心概念（先理解再动手）

- **业务对象 / 动态表单**：星空里一张单据就是一份元数据（字段、布局、操作、状态、权限的 XML 描述），
  运行时由 BOS 解释引擎加载，不需要你手工建物理表——**发布时平台自动建表/加列**。
- **FormId（表单标识）**：业务对象的唯一编码，标准单据如 `PUR_PurchaseOrder`；
  自定义单据必须用**自己的前缀**避免与标准冲突（本示例用 `SKY_`，正式项目建议用公司/项目缩写）。
- **单据模板**：新建业务对象时选“单据”模板，自带单据头、单据体（FEntity）、单据编号 FBillNo、
  单据状态 FDocumentStatus、业务日期 FDate、备注 FNote，以及保存/提交/审核等标准操作。
- **扩展 vs 新建**：给标准单据加字段/插件用“扩展”（升级安全）；全新业务才“新建”。

## 2. 示例单据设计

单据名称：**差旅费报销单**　FormId：**`SKY_ExpReimburse`**

| 区域 | 字段标题 | 标识(Key) | 字段类型 | 说明 |
|---|---|---|---|---|
| 单据头 | 单据编号 | `FBillNo` | 系统字段 | 模板自带，绑定编号规则 |
| 单据头 | 业务日期 | `FDate` | 日期 | 模板自带 |
| 单据头 | 单据状态 | `FDocumentStatus` | 系统字段 | 模板自带（暂存/已提交/已审核） |
| 单据头 | 申请部门 | `FDeptId` | 基础资料（部门 `ORG_Department`） | 可选字段，拖“基础资料”后绑定部门 |
| 单据头 | 申请人 | `FApplicantId` | 基础资料（员工 `BD_Empinfo`） | 可选字段 |
| 单据头 | 报销总额 | `FTotalAmount` | 金额 | **设为不可编辑**，由插件按分录汇总 |
| 单据头 | 备注 | `FNote` | 文本 | 模板自带 |
| 单据体 `FEntity` | 费用项目 | `FExpType` | 文本（或绑定“费用项目”基础资料/辅助资料） | 必填 |
| 单据体 `FEntity` | 金额 | `FAmount` | 金额 | 必填，大于 0 |
| 单据体 `FEntity` | 说明 | `FDescription` | 文本 | 可空 |

> 字段标识（Key）一旦发布、有数据后不要修改；标题可以随时改。

## 3. 在 BOS 设计器中新建（逐步）

1. 登录星空客户端/HTML5 端，主控台搜索打开 **BOS 设计器（BOS 集成开发平台）**。
2. 左侧选择一个业务领域/子系统（练习时可放在“基础管理”或你方二开专用领域；
   也可在动态表单分类下新建），点击工具栏 **【新建】**，打开业务对象新建向导。
3. 新建方式选择 **新建业务对象 → 单据**（不是“动态表单”空白模板；单据模板自带编号/状态/操作），
   填写：
   - 名称：差旅费报销单
   - 标识：`SKY_ExpReimburse`
4. 设计表单：
   - 从工具箱拖入 **单据体**（默认实体 Key `FEntity`，若已有则不重复加）；
   - 单据头拖入：基础资料字段 ×2（属性中分别绑定“部门”“员工”）、金额字段 ×1（标识 `FTotalAmount`，
     勾选“锁定/不可编辑”）；
   - 单据体拖入：文本 `FExpType`、金额 `FAmount`、文本 `FDescription`；
   - 在属性窗口设置标题、必填、精度（金额 2 位）、布局位置。
5. **单据编号规则**：菜单【编辑】→ 编码规则/编号规则，新增一条规则（如前缀 `BX` + 日期 + 流水），
   保存并在表单属性“编码规则”中绑定；也可在主控台“单据编号规则”基础资料中配置。
6. **操作与状态**：单据模板已内置 暂存(Save)、提交(Submit)、审核(Audit)、反审核(UnAudit)、删除(Delete)
   和“草稿→已提交→已审核”状态机，一般无需新建；本示例的插件挂到这些标准操作上（见第 4 节）。
7. （可选但推荐）菜单【编辑】→ **网络控制**，设置单据打开时的并发控制。
8. 点击 **【保存】** 保存元数据；可先点 **【预览】** 检查界面。
9. 点击 **【发布】/【同步】**（不同版本为“发布元数据/同步到数据库”）：
   平台据此创建物理表与字段，**不要手工到数据库建表改列**。
10. **授权**：用管理员账号在主控台搜索 **【业务对象功能授权】** → 选择角色 → 勾选“显示全部业务对象”
    → 找到 `SKY_ExpReimburse` → 勾选查询/新增/修改/删除/提交/审核等权限 → 授权。
11. **发布到主控台菜单**：BOS 设计器【发布】→【发布到主控台】，新增“子功能”和“子功能明细”，
    绑定本业务对象，**同时勾选桌面端和浏览器端**，发布后用户才能在主控台搜到该单据。
12. 跨环境迁移：BOS【解决方案 → 部署包管理】把自定义单据元数据打成部署包，在目标环境导入；
    插件 DLL 按《部署与调试指南》单独拷贝。

## 4. 注册本示例的三个插件

在 BOS 设计器中打开 `SKY_ExpReimburse`：

| 插件 | 注册入口 | 类全名, 程序集名 |
|---|---|---|
| 表单插件 | 【编辑 → 表单插件】 | `KingdeeSky.Plugins.CustomBill.ExpReimburseFormPlugin, KingdeeSky.Plugins` |
| 保存校验器 | 【操作列表 → 保存 → 校验器】 | `KingdeeSky.Plugins.CustomBill.ExpReimburseSaveValidator, KingdeeSky.Plugins` |
| 审核服务插件 | 【操作列表 → 审核 → 服务插件】 | `KingdeeSky.Plugins.CustomBill.ExpReimburseAuditOpPlugin, KingdeeSky.Plugins` |

审核插件会向 `T_SKY_AUDITLOG` 写记录，先在账套库执行 `deploy/Scripts/T_SKY_AUDITLOG.sql`。

## 5. 验证清单

- [ ] 主控台能搜到并打开“差旅费报销单”，新增界面字段齐全；
- [ ] 新增分录行金额默认为 0；录入各行金额后，表头报销总额自动汇总；删除分录行后总额重算；
- [ ] 费用项目为空、金额 ≤ 0、无明细分录时，界面保存被拦截；
- [ ] 绕过界面（用下面的 WebAPI 场景）保存非法数据，服务端校验同样返回错误；
- [ ] 审核总额为 0 的单据被操作插件阻断；正常审核后 `T_SKY_AUDITLOG` 出现 FormId=`SKY_ExpReimburse` 的记录。

## 6. 用 WebAPI 操作自定义单据

自定义单据与标准单据走**完全相同**的 WebAPI 端点，把 `formid` 换成 `SKY_ExpReimburse` 即可。
本代码包客户端菜单 5 已内置建单场景，数据包形如：

```json
{
  "Id": 0,
  "FBillNo": "",
  "FDate": "2026-10-08",
  "FDeptId": { "FNumber": "部门编号，App.config 可留空不传" },
  "FApplicantId": { "FNumber": "员工编号，可留空不传" },
  "FNote": "WebAPI 创建的差旅报销单",
  "FEntity": [
    { "FExpType": "交通费", "FAmount": 320.50, "FDescription": "高铁往返" },
    { "FExpType": "住宿费", "FAmount": 800.00, "FDescription": "两晚" }
  ]
}
```

查询字段示例（ExecuteBillQuery）：
`FBillNo,FDate,FDeptId.FName,FApplicantId.FName,FTotalAmount,FDocumentStatus`

## 7. 常见问题

1. **主控台搜不到单据**：未发布到主控台、未勾选桌面/浏览器端，或角色未做业务对象功能授权。
2. **发布报错“字段 Key 已存在”**：Key 与平台保留字段/同名字段冲突，换带前缀的 Key（如 `FSkyAmount`）。
3. **发布后改了字段类型/长度**：再次执行发布同步；删除已发布字段需先确认无数据，平台会提示风险。
4. **插件下拉找不到类**：DLL 未放站点 bin，或类不是 public/无无参构造（同标准单据 FAQ）。
5. **自定义单据要不要自己写 SQL 建表**：不要。物理表由发布动作自动维护，直接写表会绕过 ORM 与状态机。

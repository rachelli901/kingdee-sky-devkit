# 多环境发布与变更管理

适用版本：KingdeeSky.DevKit v1.0.3+
配套文档：《V9.1 部署操作手册》《回滚预案》《安全审计与漏洞扫描清单》《SLA 与备份恢复预案》

## 1. 目的与范围

本文档定义 KingdeeSky.DevKit 在 **dev / test / prod** 三层环境下的配置分层、环境切换、发布审批、灰度与回滚流程，使非敏感配置可按环境切换、密钥始终保留在密钥源中，并让发布具备可审批、可验证、可回退的闭环。

适用范围：WebApiClient（客户端）与 KingdeeSky.Plugins（服务端插件）的版本发布与变更管理。

## 2. 环境分层模型

| 环境 | 用途 | 配置来源 | 密钥策略 | 数据 | 变更节奏 |
| --- | --- | --- | --- | --- | --- |
| dev | 本地开发、联调 | App.config 默认 + 环境变量覆盖（`env/dev.env`） | env 环境变量 | 模拟服务/测试账套 | 随时，无审批 |
| test | 集成测试、UAT | `env/test.env` 覆盖 | env / file | 测试账套（可重建） | 需评审，低风险免审批 |
| prod | 生产 | `env/prod.env` 覆盖 | **dpapi / kms** | 生产账套（不可逆） | 需变更申请与分级审批 |

原则：

- **非敏感项**（站点地址、账套、账号、鉴权模式、密钥来源、传输安全开关）按环境通过 `KDSKY_*` 环境变量切换；不区分环境的项放 `App.config`。
- **敏感项**（密码、AppId/AppSecret、ClientId/ClientSecret、KMS Token）**始终**由 `ISecretProvider` 密钥源提供（env / file / dpapi / kms），不进入 `App.config`、不进入 `env/*.env` 文件、不进入源码。
- 环境变量文件只提交 `*.env.example` 模板，真实 `env/*.env` 不得提交（见 `.gitignore`）。

## 3. 非敏感项分层配置

优先级：**KDSKY_* 环境变量 > App.config > 代码默认值**。

| 配置项 | App.config 键 | 环境变量覆盖 | 说明 |
| --- | --- | --- | --- |
| 部署环境 | `Environment` | `KDSKY_ENV` | dev / test / prod，默认 dev |
| 站点地址 | `ServerUrl` | `KDSKY_SERVER_URL` | 生产必须 https |
| 账套 ID | `AcctId` | `KDSKY_ACCT_ID` | 各环境不同 |
| 登录账号 | `UserName` | `KDSKY_USER_NAME` | 建议用专用服务账号 |
| 鉴权模式 | `AuthMode` | `KDSKY_AUTH_MODE` | password / oauth2 / appsec |
| 密钥来源 | `SecretStore` | `KDSKY_SECRET_STORE` | env / file / dpapi / kms |
| 令牌端点 | `TokenEndpoint` | `KDSKY_TOKEN_ENDPOINT` | oauth2 专用，非敏感 |
| 允许明文 HTTP | `AllowInsecureHttp` | `KDSKY_ALLOW_INSECURE_HTTP` | dev 可 true；test/prod false |
| 允许任意证书 | `AllowInvalidCertificate` | `KDSKY_ALLOW_INVALID_CERT` | 仅本地调试 true，生产 false |

三套模板见 `env/dev.env.example`、`env/test.env.example`、`env/prod.env.example`。使用前复制为 `env/<env>.env` 并填写各环境实际值。

## 4. 环境切换与验证

### 4.1 方式一：PowerShell 脚本钩子（推荐）

```powershell
# dev / test / prod 切换 + 自检门禁（JSON）
powershell -NoProfile -ExecutionPolicy Bypass -File eng\run-env.ps1 -Environment test -Command selfcheck

# 以 test 环境配置启动交互程序
powershell -NoProfile -ExecutionPolicy Bypass -File eng\run-env.ps1 -Environment test -Command run
```

`run-env.ps1` 会自动加载 `env/<env>.env` 的非敏感项到进程环境变量、设置 `KDSKY_ENV`，然后运行客户端并以门禁结果作为退出码。

### 4.2 方式二：直接注入环境变量

Git Bash：

```bash
KDSKY_ENV=test KDSKY_SERVER_URL=https://test.kdcloud.example/K3Cloud/ \
  KDSKY_ACCT_ID=TESTACCT KDSKY_USER_NAME=Operator \
  src/KingdeeSky.WebApiClient/bin/Release/KingdeeSky.WebApiClient.exe --selfcheck --json
```

cmd：

```bat
set KDSKY_ENV=test
set KDSKY_SERVER_URL=https://test.kdcloud.example/K3Cloud/
src\KingdeeSky.WebApiClient\bin\Release\KingdeeSky.WebApiClient.exe --selfcheck --json
```

### 4.3 验证要点

`--selfcheck --json` 输出中的关键字段：

| 字段 | 含义 | 期望 |
| --- | --- | --- |
| `deploy-env` | 当前生效环境 | dev / test / prod |
| `deploy-env-source` | 环境来源 | environment / app.config / default |
| `passed`/`failed` | 检查计数 | prod 发布前必须 `failed=0` 且 `passed` 全绿 |
| `密钥 KINGDEE_*` | 密钥存在性 | `ok=true` |
| `传输协议 HTTP` 的 `warn` | 明文 HTTP 告警 | prod 不应出现 |

退出码：`0` = 通过（可发布），`1` = 存在失败项（禁止发布）。

## 5. 发布审批流程

### 5.1 变更类型与分级

| 级别 | 典型变更 | 审批要求 |
| --- | --- | --- |
| L1 | 配置项、示例数据、文档 | 记录即可 |
| L2 | 客户端代码、测试、构建脚本 | 测试负责人评审 + 技术负责人审批 |
| L3 | 插件代码、鉴权/传输安全策略、密钥存储切换 | 变更评审会 + 安全负责人 + 技术负责人审批 |
| L3+ | 影响生产账套数据的变更、回滚方案涉及数据修复 | 追加业务负责人审批，必要时高层审批 |

### 5.2 流程步骤

1. **变更申请**：填写变更记录（见第 8 节模板），说明变更内容、影响范围、回归方案、回滚方案。
2. **自检门禁**：在 test 环境运行 `--selfcheck --json`，`failed=0` 且关键检查全绿；运行全量测试（62 用例）。
3. **评审与审批**：按级别完成评审/审批并留痕。
4. **发布窗口**：生产发布建议在业务低峰窗口执行。
5. **发布执行**：打包 → 拷贝包到目标机 → 按《V9.1 部署操作手册》部署（插件需每台 APP 服务器拷贝并回收程序池/重启）→ 以 prod 环境运行 `--selfcheck --json` 验证。
6. **验证与观察**：发布后按《SLA 与备份恢复预案》监控日志、指标与告警，观察期建议 ≥24h。
7. **变更记录归档**：更新变更记录，标注结果与回滚状态。

## 6. 灰度与金丝雀发布

### 6.1 客户端（WebApiClient）

- **影子验证**：新版本先以相同配置在 test/prod 影子账套跑通读场景，确认响应与基线一致。
- **比例/分组**：通过环境变量切分（如先给少量账号、单组织使用新配置），对比 `--selfcheck` 与运行日志。
- **快速回退条件**：自检 failed>0、P95 超阈值持续 3 个采样周期、登录失败率上升 → 立即回退环境变量/切回上一版本包。

### 6.2 服务端插件（KingdeeSky.Plugins）

- **单 APP 服务器试点**：集群环境先在 1 台 APP 服务器部署并观察，再横向铺开；首次部署必须回收程序池或 `iisreset`（热更新仅对"替换已有 DLL"生效，部分补丁版本默认关闭热更新开关 `IsEnablePlugInHotUpdate`）。
- **按组织/单据试点**：插件逻辑可用组织参数开关控制影响范围时，先放开小范围组织验证业务回归。
- **回退**：将原版本 DLL 替换回目标目录 + 回收程序池；若涉及数据变更，按《回滚预案》执行数据修复脚本。

## 7. 回滚流程

完整回滚预案见 `deploy/回滚预案.md`。环境级回滚速查：

1. **判定**：确认发布失败或严重回归（业务阻断 / 数据异常 / 告警升级）。
2. **客户端回滚**：切回上一版本的 zip 包（`artifacts/KingdeeSky.DevKit-{上一版本}-*.zip`），保留当前 `env/prod.env`，重新运行 `--selfcheck --json` 确认全绿。
3. **插件回滚**：将上一版本 DLL 替换到每个 APP 服务器站点 bin，回收程序池或 `iisreset`。
4. **配置回滚**：如变更涉及 `env/*.env` / `App.config`，恢复上一版配置并核对 `deploy-env-source`。
5. **数据修复**：如已产生错误数据，按《回滚预案》数据修复章节执行（审计表引用 `deploy/Scripts/T_SKY_AUDITLOG.sql`）。
6. **复盘**：在变更记录中登记回滚原因、时间、耗时与改进项。

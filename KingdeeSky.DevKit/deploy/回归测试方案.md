# 回归测试方案

适用版本：KingdeeSky.DevKit v1.0.3+
配套文档：《多环境发布与变更管理》《回滚预案》《SLA 与备份恢复预案》《安全审计与漏洞扫描清单》《V9.1 部署操作手册》
配套模板：《回归测试用例执行记录模板》

## 1. 目的与范围

本文档定义 KingdeeSky.DevKit 的回归测试分层、用例范围、环境与数据准备、进入与退出准则、执行流程与频度、缺陷分级与回归触发策略、报告与留档要求，使每一次变更都有一条可复现、可留痕、可裁决的回归路径。

适用范围：WebApiClient（客户端集成程序）与 KingdeeSky.Plugins（服务端插件）。回归既覆盖"改完不破坏已有功能"的代码级验证，也覆盖"业务单据流转正确"的业务级验证。

## 2. 回归分层模型

| 层级 | 名称 | 测试对象 | 可执行环境 | 当前可用 | 通过准则 |
| --- | --- | --- | --- | --- | --- |
| L1 | 代码级回归 | 62 个单元用例 + 密钥扫描 + 构建门禁 | 本机（零金蝶依赖） | 可用 | 用例 62/62 通过、退出码 0，密钥扫描 0 命中 |
| L2 | 协议级回归 | mock 端到端接口流（登录/查询/建单/提交/审核/反审核/删除/下推） | 本机（Python 模拟服务） | 可用 | 全流程成功，内码、单据编号、响应与预期一致 |
| L3 | 业务级回归 / UAT | 真实单据流转、字段联动、保存校验、审核拦截与审计、下推反写 | 授权星空 V9.1 测试账套 | 阻塞（需授权环境） | 用例全通过、阻断级缺陷清零、业务方签署 |

阻塞说明：L3 依赖授权星空测试环境（V9.1 + 匹配补丁的 BOS DLL），在拿到该环境前无法编译与执行插件侧用例，属预期边界，需在交付说明中写明。

## 3. 回归范围与用例分组（L1）

当前 L1 共 62 个用例，按被测对象分 5 组：

| 组 | 文件 | 用例数 | 覆盖点 |
| --- | --- | --- | --- |
| A 鉴权 | AuthProviderTests.cs | 16 | 密码 / OAuth2 / AppID-AppSec 三种鉴权模式的登录流程、异常处理与工厂选择 |
| B 密钥与脱敏 | SecretProviderTests.cs | 15 | env / file / dpapi / kms 四种密钥源、密钥读取异常、日志与字符串脱敏 |
| C 配置与环境 | ConfigTests.cs | 9 | 非敏感项加载、KDSKY 前缀环境变量覆盖、部署环境来源、占位符校验 |
| D 客户端契约 | ClientTests.cs | 6 | 客户端构造入参校验、登录委托与结果透传 |
| E 传输安全与签名 | TransportSecurityTests.cs | 16 | HTTPS 强制策略、明文 HTTP 放行、HMAC-SHA256 签名器、请求头写入 |

逐条用例清单（62 条，含编号、业务场景、预期与执行记录栏）见《回归测试用例执行记录模板》第 3 节。

## 4. 用例到业务场景的映射

| 用例组 | 对应业务场景 | 回归层级 |
| --- | --- | --- |
| A 鉴权 | 登录鉴权方式选择、凭据缺失或错误的处理 | L1 + L3 |
| B 密钥与脱敏 | 生产凭据管理（DPAPI/KMS）、日志与报文不泄露明文 | L1 + L3 |
| C 配置与环境 | dev / test / prod 切换、门禁随环境收严 | L1 + L3 |
| D 客户端契约 | 与星空 WebAPI 的调用契约、入参合法性 | L1 + L2 |
| E 传输安全与签名 | 生产走 HTTPS、AppSec 签名请求头 | L1 + L3 |

## 5. 环境与数据准备

| 层级 | 环境要求 | 数据与前置 | 执行入口 |
| --- | --- | --- | --- |
| L1 | Windows + .NET Framework 4.x（csc 编译） | 无 | tests\run-tests.bat |
| L2 | 本机 Python 3（仅标准库） | mock 服务与预置 3 张采购订单 | KingdeeSky.WebApiClient-Demo\run-demo.bat（菜单 4 全流程） |
| L3 | 授权星空 V9.1 测试账套；专用服务账号；lib 下拷贝 BOS DLL | 测试账套、基础资料、测试单据；变更前备份确认 | lib\copy-kingdee-dlls.bat 后 build.bat，再用 eng\run-env.ps1 -Environment test 运行 |

配置与密钥：非敏感项（站点地址、账套、账号、鉴权模式、密钥来源、传输开关）由 env\test.env 提供，经 KDSKY 前缀环境变量覆盖；敏感项（密码、AppId/AppSecret、ClientId/ClientSecret、KMS Token）必须由密钥源（env / file / dpapi / kms）注入，不得写入 App.config、env 文件或源码。

降级路径：无 KMS 时改用 dpapi（Windows DPAPI + 服务账号隔离）；无 DPAPI 时改用 file 或 env；无托管 CI 时用本地 Git + 脚本化流水线人工触发。

## 6. 进入准则（Entry Criteria）

全部满足方可开始一轮回归：

1. 变更已完成并通过 L1：62/62 通过、密钥扫描 0 命中、构建全链路退出码 0。
2. 已产出可交付构建包（artifacts\KingdeeSky.DevKit-{版本}-{时间戳}.zip），并登记 Git 标签。
3. L1 / L2 环境就绪；L3 需测试账套就绪、变更前备份已确认、专用账号可登录。
4. 用例与测试数据就绪（本轮范围已选定，记录在执行记录第 1、2 节）。
5. L2 / L3 相关变更已完成审批（按《多环境发布与变更管理》的变更分级）。

## 7. 退出准则（Exit Criteria）

| 层级 | 退出条件 |
| --- | --- |
| L1 | 62/62 通过；密钥扫描 0 命中；build.bat 全链路退出码 0 |
| L2 | 8 步协议流全部成功，内码、单据编号、错误信息符合预期 |
| L3 | 用例通过率 100%；阻断级（P1/P2）缺陷清零；遗留 P3/P4 有明确结论与豁免记录；业务方 UAT 签署 |

三层同时满足方可判定"回归通过"并放行发布；任一层未通过即维持阻塞并进入缺陷处理流程。

## 8. 执行流程与频度

| 场景 | 触发 | 执行层级 |
| --- | --- | --- |
| 日常提交 / PR | 每次 push、PR | L1（CI 自动） |
| 发版前 | 版本冻结 | L1 + L2 + 性能冒烟 |
| 上线前 | test 环境验证 | L1 + L2 + L3（test 账套） |
| 上线后观察期 | 发布后不少于 24 小时 | 运行日志与指标复核、L3 关键用例抽检 |
| 缺陷修复后 | 任一 P1/P2 修复 | 受缺陷影响组 + 全量 L1 |

L1 由 tests\run-tests.bat 执行，也可由 build.bat 在"密钥扫描 -> 编译 -> 全量测试 -> 打包"链路中自动带跑；缺陷定位或按记录模板逐条取证时用 tests\run-cases.bat（支持按编号 TC-L1-001…062、按分组 A/B/C/D/E、按方法名运行，`-List` 可打印完整编号映射，用法见 tests\README.md）；L2 由 mock 演示脚本执行；性能冒烟由 perf\run-perf.ps1 执行（本地 stub 端口 18081）。

## 9. 缺陷分级与回归触发策略

| 级别 | 定义 | 处理要求 |
| --- | --- | --- |
| P1 阻断 | 登录失败、单据无法保存或提交、数据错写 | 立即停止回归，修复后重跑全量 L1 + 受影响的 L2/L3 |
| P2 严重 | 关键校验失效、审核或审计缺失、明文泄露 | 本轮必须修复，重跑受影响组 |
| P3 一般 | 非关键路径异常、提示不准确 | 记录并排期，可带豁免结论发布 |
| P4 轻微 | 文案、体验问题 | 记录，不阻塞发布 |

回归范围收缩原则：缺陷修复只影响某一组时，优先重跑该组加全量 L1；涉及鉴权、传输、配置等基础组件时，一律全量 L1 加对应 L2/L3。

## 10. 报告与留档

- 每轮回归使用《回归测试用例执行记录模板》生成一份执行记录，命名 回归记录-{版本}-{yyyymmdd-HHMMSS}.md。
- 留存内容：执行信息、环境与数据、逐条结果与证据、缺陷记录、结论与签署。
- L1 证据以 run-tests 输出的 passed/failed 汇总行为准；L2 以 mock 运行输出为准；L3 以执行记录与业务方签署为准。
- 执行记录与《多环境发布与变更管理》的变更记录互相引用；发布失败时按《回滚预案》执行回滚，并在记录中登记回滚原因与耗时。
